# MIDI 导入与导出

应用和数据集工具通过引擎中同一个 SMF 导入器读取标准 MIDI 文件。从开头到 [数据集转换配置](#数据集转换配置) 之前的内容描述的是应用，也就是默认行为。数据集配置及其验收规则放在最后。

## 导入：从 SMF 到工程

你可以导入类型 0、1 或 2 的任意标准 MIDI 文件。导入会打开一个对话框，在工程发生任何变化之前先显示将要创建的内容。

### 读取哪些内容

| SMF | 转换为 |
|---|---|
| `set_tempo`（全部事件） | 工程速度映射（分段恒定的拍） |
| `time_signature` | 工程拍号映射 |
| `key_signature` | 工程调号映射 |
| 轨道名 / 乐器名 | 轨道名，以及建议的乐器 |
| `program_change` | 乐器建议：GM 名称，如果有名称匹配的插件预设，也一并建议 |
| note on/off | 乐句音符（拍、力度、时值），保留通道 |
| CC 1、7、10、11、64、74、71 | 轨道上的自动化曲线（`mod`、`volume`、`pan`、`expression`、`sustain`、`brightness`、`resonance`） |
| 弯音 | `pitch_bend` 自动化曲线（−8192..8191 映射为 −2..+2 半音，除非 RPN 0 设定了其他范围） |
| 通道触后 | `pressure` 自动化曲线 |
| `end_of_track` | 轨道长度提示 |

每个通道只使用第一个音色切换。复音触后、之后的音色切换以及其他所有事件（SysEx、文本、标记、音乐工程中的 SMPTE 偏移）都会在导入摘要中列为已忽略。不会有任何内容未经列出就被丢弃。

### 轨道映射

对话框会给出一个映射方案，你可以修改其中任何部分：

- 默认情况下，每条 SMF 轨道成为一条工程轨道。**按通道拆分** 会把源轨道的每个通道拆成单独的轨道。它默认关闭，但通道 10 总会成为单独的轨道。
- 通道 10 成为使用 GM 音符映射的鼓轨道，除非你把它映射到某个鼓组。
- 空轨道默认被丢弃。关闭 **丢弃空轨道** 即可保留它们。
- 已被占用的名称会加上后缀。轨道不会因为重名而被合并。
- 你可以把一条 SMF 轨道映射到已有的工程轨道上（追加），也可以新建一条轨道。

追加从目标轨道最后写入的内容之后开始：乐句的结尾、片段的结尾或乐段写入的小节，取三者中最晚的一个。从这一点开始保留文件内部的时间关系。落在同一条轨道上的所有单元都从同一点开始，所以多轨文件的各声部保持同步。追加的内容是一个撤销步骤，已有内容不受影响。

### 时间

- 工程分辨率为 480 PPQ。摘要会显示源 PPQ。当 480 是源 PPQ 的整数倍时转换是精确的；否则摘要会报告残差：最大 tick 误差，以及有多少事件发生了移动。
- 速度变化写在它的精确 tick 上。音符内部的速度变化不会拆分该音符。
- 同音高的两个音符重叠时，后一个 note-on 会结束前一个音符。摘要会统计这类重叠。
- **延音踏板展开**（默认开启）在 CC64 大于等于 64 时把音符结尾延长到踏板抬起处。踏板数据同时保留为一条自动化曲线。

### 导入摘要

对话框为每条源轨道显示名称、通道、音色、音符数、找到的 CC 曲线、第一个和最后一个小节、速度变化以及被忽略的事件类型。导入完成后，对话框会继续显示摘要和新建轨道的列表，直到你关闭它，方便你核对结果。

## 导出：从工程到 SMF

导出针对一个选择范围：整个工程、一段轨道范围或一条轨道。写入之前，对话框会显示格式、PPQ、通道分配，以及下文所述的损失列表。

### 写入哪些内容

- 格式 1，带一条指挥轨，其中包含速度映射、拍号映射、调号映射和轨道名。格式 0 可供较旧的硬件使用。
- 默认 480 PPQ。对话框还提供 960，`ocp midi export --ppq` 接受 96 到 960 之间的任意值。
- 每条工程轨道对应一条 SMF 轨道。旋律轨道按轨道顺序从 1 开始分配通道，跳过 10，超过 16 后循环。通道 10 留给鼓轨道。任何分配都可以手动覆盖。
- 音符写为 note on/off，力度 1..127，时值以 tick 计。零长度的音符会被加宽到 1 tick 并计数。
- 如果轨道的乐器能映射到某个 GM 音色，就在轨道开头写入音色切换。没有 GM 映射的插件不导出音色切换，报告会统计它们。
- 自动化：有 CC 对应的控制器（volume、pan、expression、mod、sustain、brightness、resonance）导出为 CC 曲线。弯音按弯音导出。没有 CC 对应的曲线会被丢弃并列出。
- 速度、拍号和调号变化写在各自的 tick 上。

### 损失列表

损失列表总是显示。MIDI 无法承载：

- 演奏法和键位切换（除非你做了映射，否则导出为普通音符）；
- 逐音符的微分音调律；
- 插件参数，以及没有 CC 对应的参数的自动化；
- 音频片段、片段淡变和增益包络；
- 发送和总线；
- 选择范围之外的静音和独奏；
- 比离散速度事件更细的速度渐变。

落在片段滑移、循环或裁剪窗口之外的音符或击打也会丢失，报告按每次放置统计。没有任何片段放置的命名乐段永远不会被导出，同样按对象逐个统计。对话框会列出当前选择范围中出现了哪些损失，以及每种损失影响多少个对象。

## 保证

- `import → export → import` 在 1 tick 之内保留音符、速度映射、拍号映射、音色，以及 [读取哪些内容](#读取哪些内容) 中列出的 CC 曲线。
- 输出是确定的：同一工程配合同样的选项，得到逐字节相同的 SMF。
- 格式错误或被截断的文件会产生带字节偏移的类型化错误。导入器不会崩溃，也不会留下不完整的工程。
- 导入会应用到它规划时所针对的文档版本上。如果你在文件解析期间提交了修改，这次导入就过期了：它会以版本提示被拒绝，不应用任何内容，所以你的修改不会丢失。映射中提到的每个轨道索引都必须存在于导入所应用的文档中。
- 大文件（10 万个以上事件）导入时不会出现二次方级的耗时。对话框显示只会前进的进度，你可以随时取消。
- 进度包含一个阶段（`parse`、`tracks`、`clock`、`notes`、`params`、`commit`）和一个 0.0 到 1.0 的比例。每个事件和每个音符都会检查取消标志，所以取消会很快生效。被取消的导入返回类型化的 `Cancelled` 结果（不是错误字符串），工程保持原样，也不会创建临时文件。

## 在哪里找到它

导入：

1. 选择 **导入 MIDI…** 并选取文件。
2. 检查映射表：源轨道、通道、名称、音符、音色和目标轨道。
3. 设置选项：**按通道拆分**、**丢弃空轨道**、**延音踏板展开** 和 **应用速度映射**。
4. 阅读摘要并确认。

导入进行时，对话框显示当前阶段和百分比。如果你取消，它会显示一个中性的已取消状态，不显示错误。

导出：

1. 选择 **导出 MIDI…**。
2. 选择范围：**整个工程**、**轨道范围** 或 **单条轨道**。
3. 设置格式、PPQ 和通道分配。
4. 阅读损失列表并确认。

这两个命令都在工具栏的文件菜单和轨道右键菜单中。智能体使用工具 `midi_import_preview`、`midi_import_apply` 和 `midi_export`。

## 音色标识与乐器路径

General MIDI 音色号从零开始，来自共享的音乐目录。导入的音色号会精确保留在其预设和 MIDI 元数据中，即使多个音色建议的是同一个宽泛的乐器路径。

对于没有显式音色的轨道，MIDI 导出使用与播放相同的乐器映射。例如 `guitar/acoustic_steel` 是音色 25，`bass/electric_finger` 是音色 33。乐器路径键、预设音色号以及预设选择器中的 `gm:N` 标识都不受影响。

## 数据集转换配置

`oc-data::midi2dsl` 调用 `oc-engine::midi::import_smf_dataset`。它没有自己的 MIDI 解析器、时钟实现或音符与打击乐映射器。

数据集导入会保留：

- 源 PPQ，以及精确的门限与时间元数据；
- 量化后的记谱标签；
- 人性化偏移和鼓网格偏移。

同一键位上重叠的起音共享一个显式的释放。源轨道保持独立，即使其中几条使用同一个通道。控制器曲线和源音色标识保留在共同的输出模型中。

`midi_to_project` 外观接口执行严格的数据集验收：它拒绝缺少释放、需要修复零长度音符以及带时钟警告的输入。`midi_to_import` 和 `midi_bytes_to_import` 为需要审阅结果的调用方返回共享的修复与损失摘要。文件输入上限为 64 MiB。数据集配置会拒绝类型 2 文件，因为其中的序列彼此独立；请分别导入每个序列。应用导入保持自己的规则：480 PPQ、重叠时重新触发，以及可选的延音展开。

## 共享的导入资源限制

应用、界面、CLI 和数据集导入使用同一套 `ImportLimits` 默认值。面向字节的 API 会在 `midly` 构建事件向量之前检查限制。

文件入口通过有界读取器读取，并检查打开的句柄是否为普通文件。指向普通 MIDI 文件的符号链接可以使用。目录和 FIFO 会被拒绝；在 Unix 上，文件以非阻塞模式打开，这样即使路径被替换成 FIFO，打开操作也不会等待。读取过程中不断增长的文件无法绕过字节限制，界面在读取文件和导入事件时都会检查取消。

| 预算 | 默认值 |
|---|---:|
| 输入字节数 | 64 MiB |
| 源轨道数 | 4,096 |
| 源事件数与块数 | 2,000,000 |
| 音符起音数 | 500,000 |
| 候选输出音符、自动化点和时钟点 | 2,000,000 |
| 候选输出轨道单元 | 8,192 |
| 工作单元，包括重复扫描、排序和重名处理 | 200,000,000 |
| 以四分音符计的源长度 | 1,000,000 |
| 元数据和提供的名称 | 4 MiB |
| 单个编码事件体，不含 delta（包括被忽略的 SysEx/Escape） | 64 KiB |

`MidiError::LimitExceeded` 记录类型化的限制种类、上限、实际计数和字节偏移。`MidiError::code()` 返回稳定的代码，例如 `midi_bytes_limit`、`midi_events_limit`、`midi_payload_limit` 和 `midi_extent_limit`。`midi_nonregular_input` 和 `midi_input_io` 用于区分文件故障。库调用方可以通过 `*_with_limits` API 传入更小的限制。

超出限制会返回错误。导入器绝不会返回被截断或部分提交的工程。这些限制不会改变应用按 480 PPQ 读取、数据集配置保留源 PPQ 的方式，也不会改变音符门限、控制器转换或音色标识。
