# 混音器路由

发送、总线返回和单条轨道的覆盖设置，在 DSL、离线与流式音频图以及混音器中的行为完全一致。没有使用本页这些键的 `.ocp` v0.2 文档保持原来的含义。

一条轨道和一条总线的信号流程：

```
instrument → preset FX → track insert FX → PDC → polarity
   ├─ pre send  (tap) ─► send pan ─► send level ─► bus input
   └─ fader + pan
         ├─ post send (tap) ─► send pan ─► send level ─► bus input
         └─ main route ─► master / output bus

bus input ─► bus FX (+ gain automation) ─► return fader ─► mute/solo
   └─► routes (buses) / master
```

## 设备输入：音频键控与控制

一个设备可以声明多个输入。设备目录（`devices_catalog`）列出每个设备的 `ports`。端口承载 `audio` 或 `control` 之一。`sums: false` 的端口永远不进入输出求和，因此天然静音。

`compression` 声明了三个输入：

- `in`：效果链音频，参与求和；
- `key`：音频检测输入，不参与求和；
- `control`：每帧一个归一化的 `0..1` 值，不参与求和。

在轨道上用一行 `route:` 连接其中之一：

```ocp
@track bass | instrument: synth/bass
  effects:
    - compression: threshold=-24dB, ratio=4:1
  route: control kick_env -> compression
```

`route: kick -> compression` 使用默认的 `audio` 类型，送入键控输入。一个设备只接受一个检测输入，所以在同一个效果器上只能二选一。

总线效果链可以从某条轨道取检测信号。这样整个返回信号会随该轨道的电平闪避，而键控信号不会被复制进总线：

```ocp
@bus low
  routes: [master]
  effects:
    - compression: threshold=-35dB, ratio=8:1, attack=1ms, release=40ms
  route: kick -> compression
```

在一次测量中，把 65 Hz 的贝斯发送到 `low`，并在 `kick` 上放 1 kHz 的键控击打：每次击打时贝斯返回信号下降约 4 dB，两次击打之间回到单位增益。去掉这条路由后，同一条总线仅在贝斯作用下就会把自己压到约 −6 dB。因此每次击打时的下降来自键控，贝斯不会触发自己的检测器。这条路由不分频段：它衰减的是整个返回信号。

总线和主输出效果链也接受同样的写法。控制路由是路由图中的一条边，不保存在效果器上。路由图把它画成带菱形端点的虚线。把它拖到没有控制端口的设备上会被拒绝并给出提示，检查器中的控制行可以断开它。

控制信号在供给轨道的效果链之后、接收效果链之前计算，因此是采样精确的。它不会在信号路径中形成环路，一个源可以供给多个接收方。轨道不能给自己的控制输入供信号。

## 发送的取信号点

通道发送取的是插入效果器之后的通道信号：

```
instrument → preset FX → track insert FX → PDC → polarity → ┬─ pre send ─► bus
                                                            │
                                              fader + pan ──┴─ main route ─► master / bus
                                                            └─ post send ─► bus
```

按信号顺序，规则如下：

1. 取信号点位于轨道的预设效果器、插入效果链和 PDC 之后。每个发送都带有通道的插入效果。
2. 极性反转发生在取信号点之前，所以推子前和推子后发送都带有反转。
3. `pre` 发送在推子和声像之前取信号，只经过发送声像和发送电平，通道推子和声像影响不到它。
4. `post` 发送（默认）在推子和声像之后取信号。它跟随两者，包括推子自动化，因此也带有声像定律。发送自身的声像是叠加在通道声像之上的一级额外平衡。
5. 主路由（主输出，或独占的 `output` 总线）总是经过推子和声像，与发送无关。
6. 发送绝不包含其他通道的信号、总线效果链或主输出效果链。插件辅助输出是另一种取信号点：`send(<owner>.outN -> bus)` 在插入效果器之前、推子之前取信号，见 [多输出乐器](../multi-output-routing.html)（英文）。流式播放使用同样的取信号点。

取到的信号每个块向目标总线缓冲区求和一次。PDC 把发送路径对齐到总线输入，所以带有插入效果延迟的发送会等待总线的其他部分。PDC 使用的参考见 [延迟补偿](#延迟补偿)。

### 增益变化

通道推子和声像、发送电平、总线返回和主输出增益，在各自生效的位置用 10 ms 移动到新写入的值。流式播放时一个块是 4096 帧（约 85 ms）。如果控制量每个块跳变一次，就会产生咔嗒声。斜坡把同样的修改变成一段短坡，并精确落在写入的值上。

不变化的增益按一个常数应用。因此没有实时修改的工程，渲染出的采样与没有斜坡这一级的音频图相同。静音和独奏门使用同一个斜坡。已经淡出完毕的通道会被跳过，它的静音不会被斜坡带进下一个块。

斜坡与自动化相互独立。增益片段保留自己的逐采样曲线，手动斜坡只在手动修改时启动，所以正在变化的自动化曲线不会被平滑两次。

## 发送电平与余量

工程把发送存为 `0.0..=4.0` 范围内的线性增益 `amount`，这样旧文档能保留精确值。`1.0` 是 0 dB，`4.0` 是 +12.02 dB。混音器和 DSL 以 dB 显示电平：

```
level_db = 20 * log10(amount)
amount   = 10 ^ (level_db / 20)
```

- `amount = 0`（−inf）为静音。
- 每个渲染器只应用一次增益：`bus += tap * amount`。推子后发送取到的信号已经包含推子和声像，推子前发送则不包含。发送电平不会被应用两次，通道声像定律也不会在发送声像后面再应用一次。
- 发送与通道主路由并联。发送不会把通道从主输出中移除。

引擎以 `f32` 混音，内部不削波，WAV 写入器只在最后转换时限幅。发送最高可以到 +12 dB，但总线返回信号经过自身推子后必须保持在 0 dBFS 或以下。高于单位增益的发送用来更猛地推动总线效果器（饱和器或压缩器的输入），再在总线返回推子上把电平拉回来。校验器和界面会拒绝高于 +12 dB 的发送，所以每个发送的最坏情况是 +12 dB。

在轨道上，`mix: pan_law=balance` 即使两个声道采样完全相同也使用立体声平衡。居中时两个声道都保持单位增益。对齐分轨导入会为立体声 WAV 设置这一项。默认值 `pan_law=auto` 会检测插入效果器之后音频的声道宽度。

## 每个发送的声像

每个发送在总线输入处有自己的平衡，与通道声像无关。

`pan = 0` 对任何宽度都是精确的单位增益。引擎直接返回 `(1.0, 1.0)`，不做任何运算，所以没有写 `pan` 的发送不会增加任何处理，渲染结果与不加声像的发送逐位相同。

单声道取信号（两侧内容相同的单声道通道）使用通道的等功率曲线，并重新归一化，使居中为单位增益：

```
gL = √2·cos((pan+1)·π/4)
gR = √2·sin((pan+1)·π/4)
```

极左时左侧为 +3.01 dB，右侧静音，`gL² + gR²` 保持不变。

立体声取信号（左右内容独立）使用通道的平衡定律：

```
gL = clamp(1−pan, 0, 1)
gR = clamp(1+pan, 0, 1)
```

近侧保持单位增益，只衰减远侧。完全偏向一侧时远侧静音；声像 `−0.5` 得到 `(1.0, 0.5)`，即远侧 −6.02 dB。

插件辅助发送是立体声对，总是使用平衡定律。

### 单声道兼容

两种定律都让两个声道保持同相，没有延迟，也没有极性翻转，所以发送缩混为单声道时不会抵消。单声道定律保持功率（`L² + R²` 恒定）。立体声定律只衰减一侧，所以缩混后的电平会随声像变化，与立体声通道相同。发送声像在总线输入处应用，位于取信号点之后、总线效果器之前，不起第二个通道声像的作用。

单声道发送在极左时测得左侧正好为 `√2`（1.41421），右侧为 `0.0`，总功率与居中发送相同。立体声发送在 `−0.5` 时测得 `(1.0, 0.5)`。渲染测试逐采样检查这两种定律。

## 总线条：返回推子、静音与独奏

总线拥有与通道相同的三个控件，作用在总线返回处：

| 控件 | 在链中的位置 | 范围 |
| --- | --- | --- |
| `vol` | 总线效果器和增益自动化之后，静音/独奏之前 | −120…+24 dB，线性增益 |
| `mute` | 返回推子之后 | 布尔值 |
| `solo` | 属于整个路由图的独奏规则 | 布尔值 |

总线缓冲区总是会被处理，所以播放中取消静音不会让效果器尾音重新开始。之后缓冲区再乘以返回推子。

静音总线时，它的返回信号在 10 ms 内斜坡降到静音，淡出中的尾音继续送往它的路由。斜坡结束后，缓冲区在分轨采集之前被清零，总线也不再送往它的路由。

返回推子不是自动化。`gain_automation` 仍是效果链中的一级，所以自动化在返回推子之前运行，与通道插入效果器一样。

### 独奏规则

`any_solo` 同时涵盖通道和总线：

```
any_solo = any track.solo || any bus.solo

audible(bus)   = !bus.mute && (!any_solo || bus.solo || keep(bus))
audible(track) = !track.mute
                 && (!any_solo || track.solo || track.solo_safe
                     || (any_bus_solo && track routes into a kept source bus))
```

工程头部的 `solo_mode` 决定独奏向哪里传播。默认值是 `both`，即完整的图闭包。属性取默认值时，DSL 和序列化后的 JSON 都会省略它。

| `solo_mode` | `keep` / 源总线 |
| --- | --- |
| `upstream` | 被独奏的总线以及所有能到达它们的总线（它们的输入）；供给这些总线的通道保持可闻 |
| `both` | 沿总线边在任一方向上可到达的全部节点；供给被保留总线的每个通道都保持可闻 |

被独奏节点自身通往主输出的路由总是保留。被独奏的通道保留它的输出总线和两种发送取信号点，被独奏的总线保留它的输入和返回。被独奏和独奏安全的通道还会把它们的发送目标加入 `keep`。

没有“只保留下游”的模式。总线自己不产生声音：把供给它的总线静音，它的内容也就静音了；只保留它的返回而不保留输入，结果是静音。如果连输入一起保留，就成了 `both` 闭包。所以“下游”模式要么是静音，要么与 `both` 相同，现有的两种模式已经涵盖了这个路由图的全部行为。

只有在总线独奏生效时，兄弟源才会取消静音，所以只独奏通道时两种模式的渲染结果相同。差别出现在总线独奏上：如果某个返回挂在供给被独奏总线的总线上，`both` 会保留它，`upstream` 会去掉它。

下面每条结论都有对应的渲染测试：

- 两种模式下，被独奏的总线都保持其输入可闻。输入通道并联的主路由也保持可闻，因为发送不会把通道从主输出中移除。
- 被独奏的总线绝不会静音。`upstream` 保留输入并去掉旁路返回；`both` 保留旁路返回及其尾音。
- 不路由到被保留部分的直通主输出通道会被静音，包括它的发送。
- 其他通道独奏时，独奏安全的通道继续运行，它的总线返回也继续运行。
- `mute` 优先于 `solo`：被静音的总线即使被独奏也保持静音。
- 独奏某个通道不会让承载它的总线返回静音，它的推子前和推子后发送在两种模式下都保持可闻。
- 不供给任何总线的通道在两种模式下都能到达主输出。

测量值：

- `−6 dB` 的总线把返回信号精确缩放为 `0.5011872336272722`。
- 被静音的总线返回峰值为 `0.0`，直通路径不受影响。
- 总线独奏的渲染结果，与把手工算出的可闻集合写成显式静音的同一路由图逐采样相同（误差 1e-7 以内）。
- `src_a` 和 `src_b` 经 `bus_a` 供给 `main`，`bus_a` 同时供给一个混响返回轨道。独奏 `main` 时，`both` 与 `upstream` 之差的最大采样差为 `0.988592`，RMS 差为 `0.206224`（测试 `upstream_drops_the_return_that_both_keeps`）。

## 环路规则

路由图是一个有向无环图，有三种节点：

- 轨道：源，没有入向路由边；
- 总线：接收发送，路由到总线或主输出；
- 主输出：终点。

边有 `track → bus`（发送、辅助发送或独占输出）、`bus → bus`（`routes`）和 `bus → master`。

轨道发送无法闭合环路，因为轨道没有入边。辅助发送是同一种边，遵循同一规则。即使某个故障让辅助源变成了轨道输入，总线环路检查仍会发现它。

总线路由可能闭合环路：`A → B → A`。这样的路由会在三处以错误拒绝：

1. DSL 校验器报告 `Bus routing cycle detected`。
2. 界面中的总线路由修改先校验候选工程，返回错误，不改动工程。
3. 带检查的引擎音频图构建在分配任何缓冲区之前返回 `bus routing cycle: A -> B`。

渲染器还会用有界的拓扑排序给总线排序，所以未经检查的旧构造函数也不会在畸形的图上卡死。这只是防御性的兜底，带检查的构建会直接失败。

## DSL

```ocp
@track keys | instrument: synth/lead_square
  mix: vol=-6dB, pan=0.25, send(space=-6dB, pre), send(delay=25%, pan=-0.4), polarity=invert, display_name="Keys Wide", color="#ff8800", solo_safe=true

@bus space
  mix: vol=-3dB, mute=false, solo=true
  routes: [master]
@bus delay
  routes: [master]
```

| 键 | 取值 | 默认值 |
| --- | --- | --- |
| `send(bus=<level>)` | 百分比、线性数值，或最高 +12 dB 的 dB 值 | 推子后 |
| `send(bus=<level>, pre)` | `pre` 或显式的 `post` | `post` |
| `send(bus=<level>, pan=<x>)` | 带符号数值，`-1.0`…`1.0` | `0`（单位增益） |
| `send(<owner>.outN->bus=<level>)` | 插件辅助输出，`N >= 2` | 通道取信号点 |
| `polarity=` | `invert`、`normal`、`true`、`false` | `normal` |
| `display_name=` | 带引号的字符串，1-64 个字符 | 轨道名 |
| `color=` | 带引号的 CSS 颜色，1-64 个字符 | 通道条调色板 |
| `solo_safe=` | `true` / `false` | `false` |
| 总线 `mix: vol=<dB>` | −120…+24 dB | `0` dB |
| 总线 `mix: mute=true` | 布尔值 | `false` |
| 总线 `mix: solo=true` | 布尔值 | `false` |

所有键都是可选的。不含这些键的 v0.2 文件解析为旧状态：推子后发送、无发送声像、单位增益的总线返回、无静音或独奏、无极性反转、无覆盖设置。`fmt` 只在键与默认值不同时才写出它，所以旧文件可以逐字节往返。

`display_name` 只改变混音器上显示的名称。轨道的 `name` 仍是路由和引用的标识：预设、侧链和分轨继续使用它。

JSON 导出（`ocp parse --json`、工程快照）包含同样的状态：

```json
{
  "mix": {
    "sends": [{
      "target": "space",
      "amount": 0.5011872336272722,
      "pre_fader": true,
      "pan": -0.4
    }],
    "polarity_inverted": true,
    "overrides": { "display_name": "Keys Wide", "color": "#ff8800", "solo_safe": true }
  },
  "buses": [{
    "name": "space",
    "routes": ["master"],
    "effects": [],
    "gain_automation": [],
    "volume_db": -3.0,
    "mute": false,
    "solo": true
  }]
}
```

## 界面

混音器分为两栏：左侧是所选节点的检查器，右侧是路由视图。路由视图由总线图上方的工程级工具栏和总线图组成，图中显示拓扑结构：轨道、总线、主输出以及它们之间的边。

每个层级各有自己的编辑位置：工具栏创建总线，检查器编辑所选节点，连接卡片编辑所选的边。选中一条边不会改变工具栏的作用。

### 路由工具栏、节点操作和连接卡片

创建总线：

1. 在 **新总线名称** 栏输入名称；留空则使用第一个空闲的 `Bus N`。
2. 按 **+ 总线** 或 **Enter**。

新总线路由到主输出，并成为所选节点。创建是一条 `add_bus` 命令、一个撤销步骤。工具栏只有这一个操作，所以内容不随选择变化。要添加轨道，把预设拖到混音器上：轨道是源，工具栏不会创建轨道。

单击一条边即可选中连接，也可以让它获得焦点后按 **Enter** 或 **Space**。不可见的点击描边宽 12 px，所以不必精确点中那条细曲线。从边上开始的按下操作会选中它，不会开始拖动背景。选中边的同时也会选中它的源节点，于是检查器显示拥有这条边的通道。单击节点或图的背景会取消边的选择。

选中边后，检查器一栏中源节点控件下方会打开连接卡片：

- **目标** 移动所选连接。根据边的类型，它可以是轨道的独占主输出（`set_track_output`）、一个发送（`set_send_target`）或一条总线路由（`set_bus_routes`）。移动后的发送保留电平、取信号点和声像。列表不提供会与同一取信号点的现有发送重复、或会两次路由到同一目标的选项。
- 发送边显示 dB 电平、**推子前**/**推子后** 取信号点、输入声像和移除按钮。只有通道取信号点可以在 **推子前** 和 **推子后** 之间切换；辅助取信号点固定在插入效果器之前，显示为 **辅助**。
- **Escape** 离开卡片，**Delete**（或 **Backspace**）移除连接，焦点回到源节点。

在通道控件旁边，轨道可以向其取信号点尚未供给的任意总线添加发送，总线可以添加通往主输出或其他总线的路由。每项都是一条命令。

**删除总线** 按钮位于通道详情下方的 **总线操作** 卡片中。没有入边的总线会立即删除。仍有轨道输出、发送或总线路由指向的总线会被拒绝，错误信息会列出每个引用。随后的确认卡片会说明 **重新路由并删除** 会做什么：

- 指向它的轨道输出改回主输出；
- 送入它的发送被丢弃；
- 路由到它的总线，如果这是它们唯一的路由，就改回主输出。

不会有任何东西在你不知情时变成孤立状态。确认后执行一条带 `reroute: true` 的 `remove_bus` 命令。

检查器下方的通道详情保留逐个发送的列表，其中包括辅助源选择器。对 CLAP 或 VST3 预设，添加发送的那一行有一个源选择器（**主输出**、`out2`、`out3`……）和一个 **AUX** 按钮。按钮会在需要时加载乐器，并返回它声明的立体声输出对数量。之后选择器为主输出对之后的每一对提供一个条目。多输出乐器的主输出对保持不变：**主输出** 仍是 `out1`。

每个控件在一次操作中只通过工程的修改与撤销路径提交一次。dB 输入框在值改变时提交，不是每次按键都提交；开关在单击时提交；发送、路由或边的重新指向都是一条命令。总线推子、静音或独奏的修改是一条 `update_bus_mix` 命令、一个撤销步骤。

路由修改的保存方式与其他修改相同：命令会重写 `.ocp`。路由操作在保存和加载之间往返无损，渲染出的音频与在 DSL 中手写的等效路由相同。

## 不在范围内的功能

- 总线插入效果器。总线有 `effects` 和增益自动化，但没有自己的插入链编辑器。总线效果器在检查器中编辑，是一条内联效果链，没有单独的前/后两组。没有每条总线单独的插入机架。
- 总线声像。返回信号以立体声求和，没有总线平衡控件。这样独奏和返回路径中就不会出现第二种宽度定律。
- 总线级发送。总线不能以发送电平送入另一条总线。总线唯一的边是 `routes`，它传递整个返回信号。
- 在混音器中重命名路由标识。`display_name` 只改变标签，不影响引用。
- 高于 +12 dB 的发送电平。校验器和界面会强制这个上限，见 [发送电平与余量](#发送电平与余量)。
- 拖拽音频连线。编辑音频连接的方式是选中它的边再选择目标。键盘使用同样的选择方式，所以每个操作都不依赖指针。
- 辅助节点。插件额外的输出对不是工程节点，而是发送源（`owner.outN`），显示为 **辅助** 边。创建它需要知道乐器的输出对数量，所以它位于通道详情的源选择器中，不在节点的路由区域。
- 重命名总线。总线名是它的引用标识，只能在工具栏的创建栏中选定。

## 延迟补偿

一条路由的延迟量，等于其目标已经带有的延迟减去源自身的延迟：

```
delay(src -> dst) = latency(dst) - latency(src)       # never negative
```

`latency(track)` 是源报告的延迟加上它的插入效果链。`latency(bus)` 是各个源到达总线输入时累积的延迟。供给较晚目标的源会等待这个目标，而不是等待图中最慢的路径。

通往主输出的直通路由和总线返回是例外。所有路径必须在同一个采样到达主输出，所以这些路由以全局最大值为参考。这个最大值是让混音对齐且不让任何路径提前的最小参考，也是 `pre_master_latency_samples` 向渲染器报告的值。

如果一条路由的目标已经带有比源更多的延迟，源无法补上这个差。计划不会悄悄截断它，而是记录一条 `LatencyDiagnostic { source, destination, delta }`，其中 `delta` 为 `latency(source) - latency(destination)`。渲染会把它作为警告带出，`AudioGraph::validate_latency_compensation()` 会把它作为类型化错误交给校验器。目标自身的参考会吸收这个差，所以无论哪种情况，主输出混音都保持采样对齐。

每个通道用 `mix: pdc=on | off | when_recording` 选择策略：

| 策略 | 行为 |
| --- | --- |
| `on` | 补偿每条路由（默认；没有这个键的文档就是这样） |
| `off` | 不延迟这个通道的输出 |
| `when_recording` | 只在录音过程中不延迟（`AudioGraph::set_recording`） |

`off` 和 `when_recording` 两种策略按源通道生效。通道跳过补偿时，它的发送和直通路由不会被延迟，所以监听中的录音路径对齐的是时间线，而不是主输出参考。

### 手动延迟偏移

`mix: latency=<samples>` 为轨道声明额外的输出延迟，单位是采样数，可正可负。它会加到轨道报告的延迟上：

```
effective(track) = reported(track) + latency_offset
delay(src -> dst) = max(0, latency(dst) - effective(src))
```

偏移是一种校准，不会增加延迟。它告诉计划这条轨道实际晚了多少，例如外部乐器的往返延迟，或报告了错误数值的插件。计划随后从路由中准确减去这么多延迟。偏移正确时，目标的对齐不变；缺少偏移时，会表现为固定的采样偏移。

偏移只重新分配计划已经施加的延迟。它在轨道的各条主输出路由上被限制在 `-reported <= offset <= min(destination_reference - reported)` 之内。在这个范围内，每条路由的补偿都保持在 `[0, pre_master_latency_samples]` 中：延迟线不会变长，主输出参考不会移动，渲染长度也不会改变。超出范围的请求值会被截断，每条轨道给出一次警告，读数会同时报告两个数值。插件辅助输出绕过轨道输出，所以它们既不限制偏移，也不受偏移影响。

偏移属于声明的延迟，所以当 `pdc=off` 或 `when_recording` 取消补偿时它仍然生效；这些过程只是不延迟路由。`AudioGraph::latency_readout()` 为每条轨道报告三部分：

- 报告的延迟；
- 请求的和实际应用的手动偏移；
- 对每个目标：用来比较的参考、在那里施加的补偿，以及存在时的诊断差值。

界面的检查器通过 `track_latency_readout` 命令显示所选轨道的这份读数。
