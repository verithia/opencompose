# AI 助手与乐器设置

## AI 设置

1. 打开 **AI** 标签页，点击 **设置**。
2. 选择一个服务商。在端点字段中填写它的基础 URL 或完整的请求 URL。像 `https://host/v1` 这样的基础 URL 会自动补上协议路径（例如 `/chat/completions`）。
3. 填写模型 ID 和密钥，然后点击 **保存设置 / 密钥**。
4. 开始对话前，先点击 **测试连接**。

模型名称可以编辑。内置条目并不代表你的账号有权使用该模型。

每个服务商使用一种协议，在 **服务商协议** 中选择：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini Interactions 或 Gemini GenerateContent。内置目录会为它自带的服务商设好协议。

密钥保存在 macOS 钥匙串、Windows 凭据管理器或 Linux Secret Service 中，绝不写入 YAML、工程文件或浏览器存储。在 Linux 上，Secret Service（例如 GNOME Keyring 或兼容的服务）必须处于运行且已解锁的状态。凭据存储不可用时，应用会报告失败，不会退而使用不安全的位置。非机密设置保存在 `~/.opencompose/ai-providers.yaml`。

AI 助手在加载时以及每次切换服务商时读取当前服务商的密钥，并在进程存续期间记住读取结果。某个构建第一次读取它自己的钥匙串项目时，macOS 会请求你允许；请选择 **始终允许**（Always Allow），之后的读取就不再弹窗。这个询问出现在你发送任何内容之前，绝不会出现在一轮对话中：一轮对话只读取记住的结果，而这个结果可能是拒绝。如果你关掉了这个提示，这一轮会以一条指明解决办法的配置错误结束，而不会看起来像卡住了。设置中的 **重新读取密钥** 会再次向系统请求。

重新构建应用后，macOS 通常还不信任新的构建，因为它把钥匙串项目绑定到创建它的那个二进制文件。请在设置中重新保存密钥，或点击 **重新读取密钥** 并选择 **始终允许**。对话框从不显示已保存的密钥。它只报告密钥能否读取；无法读取时，显示凭据存储自己给出的信息。

保存的密钥属于一个服务商 ID 和一个确切的端点（`<provider-id>:sha256(<endpoint>)`）。修改端点不会把现有凭据转发给新服务器。保存时会删除旧条目，状态行随后显示新端点没有已保存的密钥。如果仍需要旧凭据，请在删除前选回原来的端点并保存。

- 密钥字段留空会保留已保存的凭据。
- 你输入的密钥会一直保留在该服务商的内存中，直到你保存或移除它，所以关闭对话框不会丢失它。它绝不会写入其他服务商。
- **移除已保存的密钥** 会删除该密钥。
- 删除你自己添加的服务商时，保存设置会一并删除它的密钥。

内置目录中的主机上的端点总是需要认证。向这样的端点发送请求而没有已保存的密钥时，请求会在发出前被拒绝，并指明是哪个服务商。本机回环服务器或你自己的网关可以不用密钥，它们的认证由它们自己负责。

**添加服务商** 可以从目录预设开始。预设会填好名称、协议和基础 URL，可用于 OpenRouter、Google AI Studio、DashScope、SiliconFlow、Moonshot、Zhipu、Groq、xAI 等服务商。它的模型列表一开始是空的，**获取模型列表** 会读取你账号下的模型，你也可以手动添加任意模型 ID。至少启用一个模型后，才能创建服务商。

无界面运行时，请设置 `OPENCOMPOSE_AI_KEY`。它优先于凭据存储，所以不会有进程去打开钥匙串。`/ai/complete` 也以同样方式解析凭据。

远程端点要求 HTTPS。只有本机回环地址（`localhost`、`127.0.0.1` 或 `::1`）允许 HTTP。包含用户信息、查询字符串或片段标识的 URL 会被拒绝，HTTP 重定向也不会被跟随。每个请求的连接超时为 15 秒，空闲超时为 300 秒，总时长上限为 600 秒，并且可以取消。请求文本上限为 2 MiB，响应上限为 16 MiB。失败的请求不会自动重试，因为重试可能产生费用。服务商返回的错误正文不会显示，因为其中可能含有凭据。

端点和模型支持原生函数调用时，打开 **原生工具**。关闭时，AI 助手改用完整的 JSON 文本工具请求。服务器支持 SSE（服务器发送事件）时打开 **流式响应**，不支持时关闭。

同一个对话框中的 **工程说明** 是一段写给当前工程的简短备注，例如“分轨一律输出到 -14 LUFS”或“这首歌是 D 小调，不要转调”。这段备注会放进该工程每次请求的系统提示中，绝不会出现在其他工程的请求里，长度上限为 4,000 个字符。它的保存位置以及如何计入提示预算，见[已保存的对话](../ai-sessions.html)（英文）。

发送消息时，选中的工程上下文和最近的对话会发送给所配置的服务商，工具还可能读取工程的更多部分。请只使用你放心交给它这个工程的服务商，附加的音频或图像文件也一样：应用在构建请求时会从磁盘读取附件并直接内联发送。

### OAuth 服务商

这个构建没有附带 OAuth 登录，因为其中没有打包客户端注册信息。请使用 API 密钥类服务商。

加载设置时，如果某个已保存的服务商条目使用了本构建未提供的协议或登录方式，它会被跳过，并在日志中留下警告。其他服务商照常加载，下次保存时文件中不再包含该条目。

### 可用工具与编辑策略

AI 助手提供其策略启用的所有目录工具，另加面板本地的 `edit_subtree`、`plan_update` 和 `ask_user`。AI 助手不提供哪些工具，见[让智能体作曲](manual/agents.md)。一轮对话中最常用的几个工具：

- `list_skills()` 和 `read_skill(id)` 读取内置的参考说明。
- `plugin_search(...)` 搜索内置的免费插件目录。它是只读的，从不下载或安装任何东西。
- `project_context(path)`、`tracks_list()` 和 `presets_list()` 查看当前工程。
- `project_validate(path, dsl)` 检查一个替换内容，不做任何改动。
- `edit_subtree(path, new_dsl)` 提出一个完整的替换。在 **询问** 模式下，查看差异后选择 **批准** 或 **拒绝**。批准的替换是一个可撤销的事务。没有用户可问的会话（无界面智能体）会自行应用通过校验的替换，同样作为一个可撤销的事务。

模型拿不到 shell、文件系统访问、任意 IPC 和不受限制的网络访问。唯一的安装途径是 `plugin_pull`。它默认 `dry_run: true`，只有 `dry_run: false` 时才会安装，URL 取自经过验证的目录。从 AI 助手调用时，它只安装签名索引中按校验和与大小锁定的原生插件包（VST3、VST2、CLAP、LV2）和托管的分离运行时，并拒绝需要手动操作的 DMG、PKG 和 EXE 安装程序。

编辑遵循对话的权限模式。**询问**（`require_approval`）在每次改动前征求同意，**审阅**（`autoreview`）记录每处差异后再应用，**自动**（`write`）直接应用。破坏性调用（例如删除轨道）在三种模式下都会先询问，除非你在本对话中为它选择了 **始终允许**。参见[智能体反馈循环](../agent-loop.html)（英文）。

如果在提案等待期间工程发生了变化，该提案会被拒绝；请让它重新生成，以免覆盖较新的工作。一轮对话同一时间只等待一个批准。每一轮最多 64 次模型往返，每次往返最多 32 个工具调用；达到往返上限时，会提交已经生效的编辑。

检查设置是否正常：

1. 提问：“列出轨道，然后读取贝斯轨道并提出一处修改建议。”
2. 检查工具结果和差异。拒绝第一个提案，再批准一个新提案，然后撤销。
3. 取消一次请求，确认之后没有出现编辑。
4. 重启应用，点击 **测试连接**，确认凭据仍然有效。

## 附件输入

输入框上的回形针一次附加一个文件：音频文件（`wav`、`mp3`、`aif`、`aiff`、`aac`、`ogg`、`flac`、`m4a`、`opus`）或图像（`png`、`jpg`、`jpeg`、`webp`）。附件描述中包含路径、大小和内容哈希。构建请求时，应用读取文件并内联发送。上限为每个文件 12 MiB、每条消息四个文件、每个请求 20 MB 的 base64 数据。12 MiB 到 512 MiB 之间的音频文件会作为本地引用附加：请求中只带它的路径和大小，不含音频，模型可以把路径交给分析工具使用。

能接受什么由模型声明的输入决定，拒绝发生在请求发出之前：

- 音频取决于模型的音频输入能力，它来自目录条目的 `audio_in` 标志。协议也会限制格式：OpenAI 的两种协议接受 `wav` 和 `mp3`，Gemini 的两种协议接受上面列出的所有格式，Anthropic Messages 不接受音频。
- 图像取决于合并后模型限制中的 `input.image`。内置目录没有声明任何图像输入，所以需要在 **编辑限制** 中按模型开启。图像输入关闭的模型会拒绝图像，提示中会给出模型名称以及它声明的输入（`text` 或 `text, audio`）。

AI 助手在发送前检查这些规则，请求构建器还会再执行一次。因此无界面的 `/ai/complete` 端点也会以同样方式拒绝图像，并给出同一个模型名称。被拒绝的附件会留在输入框中，换到接受图像的模型后，无需重新选择文件即可发送。

已保存的对话会保留每个附件描述。重新打开对话时，附件标签会再次出现，之后的一轮会重新发送该文件，并在发送时重新计算哈希。如果文件已不存在，标签显示 **文件已丢失**，这个附件被跳过，消息的其余部分照常发送，请求中会有一行文字注明缺失的路径。当前模型无法接受的已保存附件也按同样方式处理：标签保留，请求中用一行文字注明文件名，代替文件内容。只有本轮新加的附件才可能导致请求失败，所以对话切换到纯文本模型后仍能继续。导出的对话会列出附件名称，但从不包含附件内容。

## 模型价格与费用

AI 助手会显示一个会话在 token 上的估计费用。价格以每百万 token 计，货币与目录发布时所用的一致，数据来自 models.dev 数据集。内置快照是 `crates/oc-gui/frontend/src-tauri/ai-prices.json`，内置目录声明的每个模型对应一条记录。

没有公开价格的模型没有记录，AI 助手也不为它显示费用。它不会显示 `$0.00`，因为价格未知并不等于价格为零。最常见的情况是 Ollama 这类本地服务器，它们不按 token 计费。

费用根据服务商报告的用量计算：

- 新输入 token 按输入价格计；
- 缓存命中的输入 token 按缓存输入价格计，目录没有公布缓存价格时按输入价格计；
- 输出 token（包括推理 token）按输出价格计。

目录中定价为零的模型是免费的，费用为零。

会话总计把有价格的各轮相加。如果会话中还用过没有价格的模型，总计只显示有价格的部分，并标注为 **部分**。

在模型的 **编辑限制** 中可以设置你自己的价格。对该服务商和模型，它优先于目录价格，对话框中仍会显示目录价格作对照。

数据集变化后，刷新快照：

```sh
python3 scripts/refresh-ai-prices.py            # fetch, rewrite the snapshot
python3 scripts/refresh-ai-prices.py --check    # fail when the file is stale
```

脚本只保留内置目录声明的服务商与模型组合，所以应用无法请求的模型永远不会有价格。提交重写后的 `ai-prices.json` 及其中报告的价格，不要手动修改价格。

## 加载乐器插件

1. 用厂商的安装程序把乐器安装到该格式的标准插件文件夹中。支持的格式和搜索的文件夹见[插件](manual/plugins.md)。
2. 打开 **预设**（`P`），点击 **+**。如果乐器是新装的，点击 **重新扫描插件**，然后打开 **插件** 类别或按名称搜索。选择该乐器即可创建一个工程预设。
3. 选中这个预设。插件区域会加载它的参数，在主机能打开插件编辑器时显示 **打开编辑器**。**重新加载参数** 会重试加载，失败信息显示在面板中。原生 VST3 编辑器的托管只在 macOS 上经过验证，并不表示支持 Windows 或 Linux 上的编辑器。
4. 在插件中选好音色。在 **乐器高级设置 → 插件设置** 中，点击 **嵌入** 把状态保存在工程里，或点击 **保存** 写出一个状态附属文件。然后保存 `.ocp` 文件。音色库中的采样内容仍在外部，必须在本机安装并获得授权。
5. 用轨道的预设选择器把预设分配给轨道，或点击预设上的 **添加为新轨道** 按钮（`+↗`）。添加音符，在编曲中试听。

## Kontakt / Tokyo Scoring Strings Free

1. 在 Native Access 中安装并激活 Kontakt Player 和这套弦乐音色库，包括它的采样内容。
2. 扫描后选择 **Kontakt 8 (VST3)**，点击 **打开编辑器**，在 Kontakt 中加载你需要的小提琴或大提琴音色。
3. 按上文用 **嵌入** 或 **保存** 保存状态。

空的 Kontakt 实例并不是已加载的弦乐乐器。

一开始请为每个乐器或音色单独建立一个命名预设。把一条轨道路由到它，并让轨道的 MIDI 通道与加载的乐器保持一致。按音色库的要求设置力度层（通常是 CC1）和表情（通常是 CC11），只靠音符力度是不够的。请对照音色的说明检查演奏法和键位切换，因为单靠音符重叠并不能保证真实的连奏效果。保存的状态可以恢复音色选择，无需每次渲染都重新打开编辑器。但它不会分发采样、不能绕过激活，也不能让每个音色都同样逼真。

选择器中的 **弦乐** 类别列出的是 General MIDI SoundFont 音色，不是 Kontakt 音色库。要使用 Kontakt 音色库，请选择 **插件 → Kontakt**。

## 验证范围

自动化测试覆盖传输层的认证、脱敏和重定向策略，流式工具参数，有边界的工具执行，以及仅凭确认才生效的编辑。浏览器测试在不使用付费 API 的情况下演练设置和提案接受流程。macOS 原生凭据存储有一个使用临时账号的往返冒烟测试。真实服务商与模型的兼容性需要你的密钥才能验证。Windows 和 Linux 上的凭据与插件路径，需要在这些平台上测试后才能为发布版本认证。

实现参考：[keyring](https://docs.rs/keyring/3.6.3/keyring/)、[reqwest redirect policy](https://docs.rs/reqwest/0.12.28/reqwest/redirect/struct.Policy.html)。

## 内置参考技能

应用内置一批简短的技能，每个都标有类别，例如编排、混音、制作或工作流程。在提出编辑之前，模型可以调用 `list_skills` 和 `read_skill` 阅读相关说明。你不需要安装任何东西，也不需要运行检索服务。你可以把自己的技能放在 `~/.opencompose/ai/skills/<id>.md`；用户技能不能使用与内置技能相同的 id。技能不授予训练权利，也不授予任何工具，编辑仍遵循对话的权限模式。内置说明位于 `crates/oc-gui/frontend/src-tauri/src/ai/skills/builtin/`。

试着这样提问：“列出你的内置技能，读取 unmask-kick-and-bass 技能，在提出任何修改之前先查看我的贝斯轨道。”工具日志中应出现一次技能列表和一次技能读取。在 **询问** 模式下，批准编辑之前工程不会改变。
