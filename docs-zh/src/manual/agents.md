# 让智能体作曲

图形界面运行时会提供一个仅限本机回环地址的 HTTP API。外部智能体通过它读取和编辑当前打开的工程，无需模拟屏幕操作。内置的 AI 助手使用同一套工具目录。

## 连接

图形界面在启动时开启服务器：

- 地址：`http://127.0.0.1:38642`，被占用时依次尝试其后 20 个端口中的第一个空闲端口。`OPENCOMPOSE_AGENT_PORT` 可以修改起始端口。
- 凭据：`~/.opencompose/agent.json` 中保存 `{ "port", "token", "pid", "version" }`。以 `X-OpenCompose-Token: <token>` 或 `Authorization: Bearer <token>` 的形式发送令牌。

| 路由 | 用途 |
|---|---|
| `GET /health` | 存活状态和版本；无需令牌。 |
| `GET /tools` | 以 JSON 返回工具目录。 |
| `POST /call` | 调用一个工具：`{"tool": "...", "args": { ... }}`。 |
| `POST /mcp` | JSON-RPC 2.0 MCP：`initialize`、`tools/list`、`tools/call`。 |
| `GET /ai/tools` | AI 助手的工具，可用 `?toolsets=a,b` 缩小范围。 |
| `GET /ai/toolsets` | 内置和用户自定义的工具集。 |
| `POST /ai/complete` | 代替 AI 助手向服务商发起一轮请求，供无界面驱动程序使用。 |
| `POST /ai/turn` | 在后端循环中执行完整的一轮智能体对话，没有人在场应答。 |
| `POST /ai/steer` | 把一条用户消息送入正在运行的一轮。 |
| `POST /ai/cancel` | 停止正在运行的一轮：`{request_id, session_id}`。 |

如果你要打开的工程被另一个进程占用，调用会返回 409，`kind` 为 `project_in_use`，你自己的文档不会被替换。如果某个已保存的对话被另一个进程打开，调用会返回 409，`kind` 为 `session_in_use`。这条规则适用于 `/ai/complete`、指明了会话的 `/call` 请求以及 `POST /ai/turn`。

要执行完整的一轮，发送 `POST /ai/turn`，带上 `provider`、`messages`（系统消息，以及最多一条用户消息）、`session_id` 和绝对路径 `project_path`。`toolsets`、`label` 和 `request_id` 是可选的。如果用 `request_id` 为这一轮命名，就可以在它运行时进行引导或停止。由于没有人在场应答，`Confirm` 类调用会被拒绝而这一轮继续进行，通过校验的 `edit_subtree` 会在这一轮内直接应用。响应是带 `ok` 的本轮结果。

`/call` 的返回为 `{"ok": true, "result": ...}` 或 `{"ok": false, "error": "..."}`。如果某个内置技能能解释这次拒绝，返回中还会带 `"skill": "<id>"`，用这个 id 调用 `read_skill` 即可读到说明。`error` 文本本身不受影响。MCP 路由按标准 JSON-RPC 2.0（`initialize`、`tools/list`、`tools/call`）应答，协议版本为 `2024-11-05`；调用失败时，同样的提示会作为第二个 `text` 块返回。

目录端点报告当前可用的工具。读取、编辑、走带、渲染和分析与 AI 助手共用同一套实现，AI 助手按其工具策略提供其中的一部分。

要浏览制作领域，用 `id: "production-curriculum"` 调用 `read_skill`。再加上 `topic: "Singeli"` 或其他曲风、场景、领域、技法，即可读到该主题的练习和听辨要点。只给出部分主题名时，返回匹配的标签。

对于音频片段，`audio_clips_list` 返回片段列表和工程修订号。`audio_clip_set_playback` 编辑速度、音高、共振峰和变速锚点；传入 `stretch_to` 可以缩放映射，并让片段终点随之移动。`audio_clip_edit_range` 用于切分或裁剪，不缩放映射。比例示例见 `align-and-stretch-audio` 技能。编辑前后请试听同一段范围。

## 可以让它做什么

| 方面 | 示例 |
|---|---|
| 工程 | 读取文档、列出轨道/预设、查看子树、校验候选编辑、设置速度和拍号映射 |
| 编辑 | 修改混音、添加/移除效果器、添加/移除总线和路由、创建、复制和重命名轨道与预设 |
| 走带 | 播放、暂停、停止、定位、读取走带状态 |
| 渲染 | 渲染混音的一段窗口（可选按轨道输出分轨），或导出整首歌的分轨 |
| 分析 | 测量 WAV、比较两次渲染 |
| MIDI | 预览、应用和导出 MIDI |
| 交接 | 把同源的 WAV 分轨和可选的 MIDI 导入一个已保存的空工程 |
| 历史 | 撤销、重做、读取撤销状态、列出撤销历史 |
| 注册表 | 列出设备及其参数、搜索插件目录 |

把导出的编排交给智能体：

1. 保存一个空工程。
2. 把对齐好的 WAV（如有 MIDI 也一起）放进工程文件旁边的 `handoff` 文件夹。
3. 让智能体用 `import_aligned_stems` 导入这些文件。

如果要自己从其他文件夹挑选文件，使用 **文件 → 导入对齐的分轨…**。

`render_range` 在带与不带 `tracks` 时行为不同：

- 不带 `tracks` 时，它返回完整混音中精确的一段，包括在窗口之前就开始的效果器尾音。可以用 `start`/`end`（秒）或 `start_bar`/`end_bar`（从 1 开始计数）指定窗口，但不能同时使用。窗口最长 600 秒。小节按写入的速度和拍号映射换算，所以段落重复时请用秒。
- 带 `tracks` 时，它从窗口起点复位后渲染一段独奏窗口，结果不是完整混音的切片。用它来试听一组分轨，不要拿它和完整渲染比较。要得到与总输出对齐的分轨，传 `stems: true` 且不带 `tracks`，分轨就来自同一次完整混音渲染。

`audio_analyze` 返回采样峰值、RMS、峰值因数、综合 LUFS（无定义时为 null）、真峰值、十个倍频程频段、频谱峰、立体声相关性和中/侧比、静音区域以及发声段落。

`audio_compare` 返回电平和各倍频程的差值，三分之一倍频程、MFCC 和 LSD 形状项，对齐重叠部分的最大采样差，相关性和对齐延迟，带状 DTW 摘要，YIN 风格的音高诊断，以及分开计算的起音强度项和每秒事件数项。默认情况下，它拒绝比较采样率或长度不同的两个文件；传 `allow_mismatch: true` 可以强制比较。绝对得分的 `value` 采用 v1.3.0 公式，`previous_value` 给出 v1.2.0 的数值。

## 事务模型

一批编辑要么作为一个整体进入工程，要么完全不生效。

- `transaction_begin` 为工程、DSL 文本、已修改标志、文件路径和撤销标记拍下快照，并返回基准修订号。
- 在打开的批次中，编辑不会各自发布修订号。第一次修改会标记事务，修订号停留在基准值，批次中的每次调用都可以用这个基准值作为 `expected_revision`。
- `transaction_commit` 只发布一个修订号。它把整批编辑合并为一个撤销步骤，记录批次基准与最终状态之间的类型化变更。撤销一次即回到批次之前的工程，重做一次即重新应用整批编辑。
- `transaction_rollback` 按字节恢复快照，删除该批次的撤销和重做条目，并把修订号向前推进，使过期的 `expected_revision` 校验失败。
- 失败的修改不会改变任何内容，批次保持打开。`dispatch` 把错误作为调用结果返回，之前的编辑仍留在批次中。客户端直接拥有的批次只有显式调用 `transaction_rollback` 才会丢弃。提交失败时，批次对其所有者保持打开。
- AI 助手的一轮或无界面智能体的一轮拥有自己的批次。无论这一轮如何结束（回答、取消、失败、超时或达到轮数上限），循环都会提交批次，所以停止前已生效的编辑会被保留。已不存在的一轮遗留下来的批次（`panel:` 或 `turn:`）只会提交，从不回滚：下一轮会提交它，`ai_batch_recover` 也会。
- 撤回（recall）是 `ai_recall {session_id, index, undo_edits, confirmed, token?}`，只对用户自己发送的消息提供。它在该消息之前截断对话，并返回该消息的文本和附件。
  - 带 `undo_edits` 时，它还会把工程历史光标移回该消息记录的位置。这是一次历史跳转，重做即可还原。
  - 如果会撤销到本对话智能体以外的人所做的编辑，第一次调用会给出一个令牌，需要第二次调用回传该令牌来确认。
  - 如果截断失败，光标、文档及其历史都会原样恢复。
  - 有一轮正在运行或有批次打开时，撤回会被拒绝。对于针对另一个工程文件发送的消息，或没有记录位置的消息，`undo_edits` 会被拒绝。
- 批次打开期间，保存、撤销和重做都会被拒绝。因此崩溃不会在磁盘上留下应用了一半的编辑，也不会在批次之下回退历史。`project_open` 和 `project_new` 会取消批次，因为它们替换了整个会话。`project_new` 接受一个绝对 `.ocp` 路径和可选的 `starter` 模板，写出文件，并拒绝已存在的路径。
- 对 `expected_revision` 而言，`transaction_begin` 也算一次修改。

在修改类工具上，把你最后看到的修订号作为 `expected_revision` 传入。不匹配时调用失败，较新的工作不会被覆盖。完整约定见[智能体反馈循环](../../agent-loop.html)（英文）。

## 内置 AI 助手

侧边栏的 **AI** 标签页是一个聊天客户端，使用同一套工具，只是去掉了会越出面板范围的那些。

- 它提供面板策略启用的所有目录工具，另加三个面板本地工具：`edit_subtree`、`plan_update` 和 `ask_user`。启用的工具集随目录变化。
- AI 助手不提供：插件扫描和加载、原生插件窗口、把插件状态写入文件、SoundFont 的安装和删除、内容库写入、`render_offline` 和 `render_stems`、主机音频设备配置、设备级静音、列出文件系统路径的工具，以及主机能力查询。`render_offline` 和 `render_stems` 会不加限制地渲染整首歌，对面板来说太慢；请使用 `render_range`，需要分轨时加上 `stems`。AI 助手可以用 `plugin_pull` 安装插件，但只限签名索引中按校验和与大小锁定的原生插件包（VST3、VST2、CLAP 或 LV2）和托管的分离运行时。
- `edit_subtree` 替换一棵完整的子树。它先校验替换内容，然后由对话的权限模式决定后续：在 **询问**（`require_approval`）模式下，改动以差异行显示，并在卡片上征求你的同意；在 **审阅**（`autoreview`）模式下，记录差异行后应用；在 **自动**（`write`）模式下直接应用。一次已应用的替换是本轮批次中的一个撤销步骤。无界面的一轮没有人可问，会在同一轮内自行应用通过校验的替换（见[智能体反馈循环](../../agent-loop.html)（英文））。
- 输入 `/goal <text>` 设置对话目标，用目标标签上的清除按钮将其移除。目标和计划随对话一起保存。模型每一轮都会读取它们，输入框会显示目标和一条计划栏，智能体通过 `plan_update` 更新它们。回退到目标或计划变更之前，会恢复之前的版本；分叉会保留它复制时的状态。
- 当需要由你做决定时，`ask_user` 会向你提一个问题，最多提供六个简短选项，或允许自由输入。回答必须是所提供的选项之一。只有问题允许时才接受自由输入，且不超过 4,000 个字符。无界面的一轮没有人回答，会以 `answered: false` 继续。
- 在猜测名称之前，智能体会先用 `project_search` 搜索工程（轨道、预设、乐段、总线、段落、标记、效果器和乐句），并得到可寻址的路径。
- 每一轮最多 64 次模型往返，每次往返最多 32 个工具调用。达到往返上限的一轮会提交它已应用的编辑。在最后四次往返中，以及上下文占比达到 60 % 和 75 % 时，会显示一条预算提示。
- 服务商设置要求使用 HTTPS，本机回环地址除外。密钥保存在操作系统的凭据存储中，绝不写入工程或 YAML。非机密设置保存在 `~/.opencompose/ai-providers.yaml`。
- AI 助手会把选中的工程上下文和最近的对话发送给你的服务商。对于配置为接受音频的模型，请求中还可以包含你附加的音频，以及 `audition_range` 返回的渲染片段。音频的限制和发送方式见[智能体反馈循环](../../agent-loop.html)（英文）。AI 助手不会给模型提供 shell、任意文件访问或不受限制的网络访问。

工具约定和服务商策略见 [AI 与插件](../ai-and-plugins.md)。
