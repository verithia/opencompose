# OpenSynth

OpenSynth（`builtin.open_synth`）是内置合成器。轨道通过预设来使用它：

```ocp
@preset bass
  source: builtin
  plugin: "builtin.open_synth"
  params: {synth_version: 2, osc.a.waveform: 1, osc.a.level: 0.74,
           sub.level: 0.42, filter.cutoff: 740Hz, filter.resonance: 0.32,
           filter.env.amount: 3.8, amp.attack: 0.004s, amp.decay: 0.18s,
           amp.sustain: 0.62, amp.release: 0.14s,
           voice.mono: true, voice.legato: true, voice.glide: 0.07s,
           output.gain: 0.26}
```

`params:` 是由音色补丁字段组成的扁平 `key: value` 映射。窗口里的音色补丁编辑器（见[主窗口](gui.md)）写入的也是这张映射，所以用鼠标调出来的音色补丁和手写的完全通用。`voice.mono`、`lfo.sync`、`mod.N.bipolar`、`fx.N.enabled` 这类开关接受 `true`/`false` 或 `1`/`0`，两种写法表示同一个值。

下文每个键的实现都在 `crates/oc-synth-core/src/synth.rs`。声明式列表在 `crates/oc-device-schema/src/synth.rs`，编辑器的下拉菜单和标签由它生成（`crates/oc-gui/frontend/src/data/synthCatalog.gen.ts`），因此引擎接受的每个调制源、调制目标、滤波器模型、扭曲（warp）编号和效果器模块，编辑器里都有。本章的枚举编号与这份目录一致。

## 出厂音色补丁 {#factory-patches}

工作台标题栏中的音色补丁字段显示工程预设的名称。名称后面较小的标签记录这些数值的来源：出厂音色补丁名、用户库条目或导入的文件名。这个标签保存为预设的 `patch:` 字段，所以重新打开工程时仍能看到来源。

点击该字段（或它的 `▾`）打开预设浏览器。浏览器列出出厂音色库和 **用户库** 两部分，按类别分组，并带搜索框。**加载** 是另一个操作：它打开文件选择器，把一个外部预设文件导入当前工程预设（见[预设导入](#preset-import)）。

这个乐器自带四个原创音色补丁（`Init`、`Neon Bass`、`Glass Pad`、`Pulse Pluck`）和 62 个分类预设：贝斯 10 个、主音 10 个、铺底 12 个、拨弦 9 个、键盘 8 个、铜管 6 个、效果 7 个。因此出厂部分共列出 66 个音色补丁。[OpenSynth 出厂预设](../factory-presets.md)逐一列出它们及各自的用途。每个类别有一个标题，圆点标出当前预设是从哪一行加载的。

### 生命周期

音色补丁属于工程本身，不会回头引用出厂音色库。

- **重命名…** 重命名 `@preset`，并在同一个撤销步骤里改写所有轨道、乐段和 `extends:` 引用。名称是预设在工程内的身份；`patch:` 标签只记录来源，解析引用时从不使用它。
- **复制** 和 **另存为…** 复制预设的参数和效果链，并让使用它的轨道改用副本。副本和原件相互独立，改动其中一个不会影响另一个。引擎测试会在编辑副本前后各渲染一次原轨道，要求两次的采样完全相同。
- **保存到音色库…** 以你输入的名称把当前生效的音色补丁写入用户库。基于文件的 OpenSynth 音色会连同波表和收集到的采样文件一起保存为原生状态，所以源工程移动后它依然可用。
  - 要迁移音色库，复制整个目录（包括 `assets/`），并在启动应用前把 `OCP_PRESET_LIBRARY_DIR` 设为新位置。已有工程会记住加载时的位置，所以需要在这些工程中重新加载库里的音色补丁。
  - 用 **另存为…** 把工程保存到别的文件夹时，会收集工程用到的库状态，并在副本中保存相对于工程的路径。
  - 从浏览器删除条目时，已收集的资源会保留，供已经使用它们的工程继续使用。
  - 托管的效果器仍然需要对应的插件和外部内容。
- **共享音色…** 写出一个 `.ocppatch` 文件，其中包含当前生效的 OpenSynth 音色、它的本地采样、你改写过的参数和插入效果链。在另一台机器上，在 OpenSynth 编辑器中选择 **加载** 并选中该文件。应用会把它加入音色库，并加载到选中的预设中。如果名称已被占用，应用会添加一个带编号的副本。托管的插入效果器仍然需要已安装的插件和外部内容。

  由工程中某条轨道或总线触发侧链的压缩器或其他插入效果器，无法放进自包含的预设。共享前，请移除外部侧链源，或把该插入效果器切换为内部检测。应用也会拒绝加载带外部侧链的音色包，否则侧链会被绑到接收方一条不相关的轨道上。

对智能体来说，对应的操作是 `preset_bundle_export` 和 `preset_bundle_import`。它们通过已保存工程的 `handoff/` 文件夹交换带编号的文件。导出需要已提交的工程快照。导入会以一个可撤销的编辑加载一个已有的 OpenSynth 工程预设，并在音色库中保留一份副本。参数说明见[智能体工作流程](../../agent-loop.html)（英文）。

当一个 OpenSynth 预设继承自另一个预设时，编辑器显示的是生效后的参数值。调整控件会在选中的子预设上写入覆盖值。继承来的插入效果器排在子预设自己的插入效果器之前。要编辑这些继承的效果器，请选中父预设。

### 整体加载与重置规则

一次加载会在同一个撤销步骤中替换整个对象：参数、预设的 `effects:` 链和 `patch:` 标签。它不会与原有数值合并。加载的音色补丁没有声明的键一律回到音色补丁默认值。默认值就是 `Init` 音色补丁使用的那张表，涵盖振荡器、副振荡器、滤波器、全部四个包络、LFO、调制槽、宏和步进音序器。同理，`fx.count: 0` 会清空合成器效果架。依次加载 A、B、A，得到的参数集与 A 完全一致；有一个 Rust 测试会比较完整的预设快照。

这批参数是规范化的：每个键只出现一次，所以同一个音色补丁加载两次，参数不变。如果其中有合成器不认识的键，整批参数都会被拒绝，错误信息列出这些键名。该信息直接显示在合成器工作台中（`role="alert"`），而不只出现在全局状态栏里。

### 浏览与试听

在浏览器中：

- `↑` 和 `↓` 移动高亮。
- **Enter** 加载高亮的音色补丁，双击则加载指针下的那一行。
- **Esc** 或点击浏览器外部会关闭浏览器，预设保持不变。

加载进行时，标题栏字段、**加载** 按钮和各行的试听按钮都会禁用，直到写入完成，所以双击不会提交两个重叠的编辑。

行上的 `▶` 试听该音色补丁而不加载它。候选音色会通过与预设预览相同的音频图完整渲染，所以它自己的 `effects:` 链也会生效。随后它的综合响度会被匹配到出厂音色库的参考值 −17.2 LUFS。响度表采用 BS.1770-4，与渲染器和分析工具使用的相同；−17.2 LUFS 是 62 个分类音色补丁在试听乐句上测得的中位数。增益限制在 −18/+12 dB 之间，并保留 0.5 dBFS 的峰值余量，所以很安静的音色补丁也能听清而不会削波。未匹配时，整个音色库的响度相差 14.9 dB；匹配后差距小于 0.4 dB，所以逐个切换时你听到的是音色差异，而不是音量差异。

试听播放的是裸音色补丁。候选音色自己的效果链会生效，但轨道的插入效果器、所在总线和主输出链都不参与，因为浏览器没有轨道上下文。每一行都播放同一段六个音的乐句。新的试听会替换上一个；`■`、**Esc** 或关闭浏览器会停止试听。工程不会有任何变化：不会标记为已修改，也没有撤销步骤，已加载的预设保持原样。

### 用户库

用户库位于 `~/.opencompose/presets`，或 `OCP_PRESET_LIBRARY_DIR` 指定的目录。每个音色补丁是一个 JSON 文件 `<name>.ocp-preset`，保存名称、类别、标签、来源、参数和效果链。保存时先写入同一目录中的临时文件，再通过重命名发布，所以保存中断时原文件完好无损。

用已有名称保存会替换该条目。API 也接受 `overwrite: false`，这时保存会被拒绝并给出可读的错误；测试用它来固定重名策略。两个名称经过清理后若得到相同的文件名，会加上稳定的哈希后缀，互不覆盖。无法解析的文件会被跳过，并在工作台中显示警告，音色库的其余部分照常加载。两个文件声明同一个名称时，保留第一个，并对第二个给出警告。

## 振荡器

OpenSynth 有三个振荡器（A、B、C）、一个副振荡器、一个噪声源和一个环形调制器。

| 键 | 含义 |
|---|---|
| `osc.<x>.waveform` | `0` 正弦，`1` 锯齿，`2` 方波，`3` 三角，`4` 波表，`5` 颗粒，`6` 频谱 |
| `osc.<x>.level` | 0–1 |
| `osc.<x>.semitones` | 粗调（A：±48，B/C：−24…+24） |
| `osc.<x>.pan` | −1…1 |
| `osc.<x>.pulse_width` | 0.05–0.95 |
| `osc.<x>.wavetable_position` | 0–1 帧位置 |
| `osc.<x>.warp_mode`、`.warp_amount`、`.warp_var` | 第一个扭曲槽 |
| `osc.<x>.warp2_mode`、`.warp2_amount`、`.warp2_var` | 第二个扭曲槽 |

`<x>` 为 `a`、`b` 或 `c`。扭曲在读取波表之前作用于相位，并且按发声单独计算，所以它会改变每个音符的音色。`warp_amount` 设定深度，`warp_var` 是该形状的第二个控制量。第二个槽（`warp2_*`）在第一个槽之上再叠加一种映射。

`warp_mode` 是数字编号：

| 编号 | 类别 |
|---|---|
| `0` | 关闭 |
| `1` | 同步 |
| `2`–`15` | 相位映射：弯曲、PWM、不对称、翻转、延迟线、重映射、量化、奇偶 |
| `17`–`18` | 滤波扭曲；可选，尚未实现 |
| `19`–`32` | 波形整形 |
| `33`–`65` | FM、PD、AM、RM 系列；可选，读取结果不变 |
| `66`–`69` | 固定的 `1 - amount` 增益 |

滤波扭曲 `17` 和 `18` 在其系数公式确定之前都按关闭处理。编辑器显示全部 70 个编号，并标出其中 35 个暂时没有可闻效果的编号。

副振荡器的键有 `sub.level`、`sub.semitones`、`sub.fine`、`sub.pan`、`sub.waveform`（`0` 正弦，`1` 圆角矩形，`2` 三角，`3` 锯齿，`4` 方波，`5` 脉冲）、`sub.initial_phase` 和 `sub.contiguous_phase`。噪声源和环形调制器分别有 `noise.level` 和 `ring.level`。

`wavetable.file` 加载自定义波表，由编辑器的波表浏览器设置。相对路径以工程目录为基准解析，详见 [.ocp 文件](dsl.md)中的预设部分。

## 齐奏

| 键 | 作用于 |
|---|---|
| `unison.voices`（1–16）、`unison.detune`（0–100 音分）、`unison.width`（0–1） | 振荡器 A |
| `osc.b.unison`、`osc.b.detune`、`osc.b.width` | 振荡器 B |
| `osc.c.unison`、`osc.c.detune`、`osc.c.width` | 振荡器 C |

每个齐奏声部都从各自确定的相位开始。相位的种子由振荡器槽位和声部序号决定，与音符和混音无关。随后由失谐和宽度把声部展开。失谐为零的一层会让所有声部保持在共同的起始相位上，因此声部之间保持相干，不会相互抵消。

## 滤波器

共有两个滤波器，各自有独立的模型和模式，另外还有一个滤波包络。

| 键 | 含义 |
|---|---|
| `filter.cutoff` | 20 Hz–20 kHz |
| `filter.resonance` | 0–1 |
| `filter.drive`、`filter.wet` | 滤波前驱动、干/湿比 |
| `filter.mode` | `0` 低通，`1` 带通，`2` 高通，`3` 陷波 |
| `filter.model` | 见下文 |
| `filter.keytrack`、`filter.keytrack.origin` | 截止频率跟随音高；原点以 MIDI 音符表示 |
| `filter.env.amount` | 滤波包络深度，−8…+8 |
| `filter.routing` | `0` 串联（A→F1→F2），`1` 并联 |
| `filter2.*` | 第二个滤波器；`filter2.enabled`（0/1）控制其开关 |

滤波器模型（`filter.model`）：

- `0` 两极点状态变量
- `1` 四极点梯形
- `2` 脏梯形
- `3`/`4` 旧版三极点和单极点梯形
- `5` 一阶抽头
- `6`/`7` 三极点和四极点状态变量级联
- `8`–`11` 每倍频程 6、12、18、24 dB 的梯形抽头

编辑器在两个滤波器上都提供全部十二种模型。各系列的谐振规律、通带修正和实测斜率见[滤波器特性](../../filter-character.html)（英文）。

## 包络

| 包络 | 键 |
|---|---|
| 振幅 | `amp.attack`、`amp.decay`、`amp.sustain`、`amp.release`、`amp.curve` |
| 滤波 | `filter_env.attack`、`.decay`、`.sustain`、`.release`、`.curve`（以及 `filter.env.amount`） |
| 包络 3 | `env3.attack`、`.decay`、`.sustain`、`.release`、`.curve` |
| 包络 4 | `env4.attack`、`.decay`、`.sustain`、`.release`、`.curve` |

`curve` 会弯曲该包络的每一段。振幅包络的起音最短为 1 ms，所以起音为零时仍从静音开始。调制包络保留瞬时起音。参见[调制](../../modulation.html)（英文）。

## LFO

共有十个 LFO。LFO 1 使用 `lfo.*`，LFO 2–10 使用 `lfo2.*` … `lfo10.*`，字段相同。

| 键 | 含义 |
|---|---|
| `lfo.rate` | 0–100 Hz |
| `lfo.rate_x10` | 把自由速率乘以十 |
| `lfo.shape` | `0` 曲线，`1` 路径，`2` 混沌 A，`3` 混沌 B，`4` 随机保持 |
| `lfo.shape.points`、`.x`、`.y`、`.curve` | 断点形状（数组；由编辑器绘制） |
| `lfo.sync`、`lfo.sync_div` | 速度同步；`sync_div` 是以拍为单位的 43 级刻度的索引（第 22 级 = 一拍） |
| `lfo.division` | 已停用的六级选择器，为旧音色补丁保留 |
| `lfo.retrigger`、`lfo.phase` | 音符按下时重新触发；起始相位，单位为度 |
| `lfo.smooth`、`lfo.rise`、`lfo.delay` | 单极点平滑、淡入延迟和上升时间 |
| `lfo.bend` | 已停用的整周期相位偏斜 |
| `lfo.pitch` | 仅 LFO 1：直接颤音深度，单位为音分 |

形状输出为单极性，范围 0–1。调制槽的 `bipolar` 标志会把它重新居中。

## 调制矩阵与宏

调制路由为 `mod.1` … `mod.64`，每条路由有以下字段：

```ocp
params: {mod.1.source: 0, mod.1.destination: 4, mod.1.amount: 0.2,
         mod.1.curve: 0, mod.1.slew_up: 0.01s, mod.1.slew_down: 0.05s}
```

| 字段 | 含义 |
|---|---|
| `mod.N.source` | `0` LFO 1，`1` 滤波包络，`2` 力度，`3`–`6` 宏 1–4，`7` 键盘跟随，`8` 触后，`9` 调制轮，`10` 步进音序器，`11`–`19` LFO 2–10，`20` 包络 3，`21` 包络 4，`22`–`25` 宏 5–8，`26` 振幅包络，`27` 弯音，`28` 音色（CC74） |
| `mod.N.destination` | `0` 滤波截止频率，`1` 音高，`2` 振荡器混合，`3` 谐振，`4` 立体声宽度，`5` A 脉宽，`6` 环形调制电平，`7` A 波表位置，`8` 振荡器 B 调音，`9` 滤波驱动，`10` 振荡器 C 电平，`11` C 波表位置，`12`–`14` 滤波器 2 截止/谐振/驱动，`15` 发声振幅，`16`–`21` A/B/C 的扭曲与扭曲 2 深度，`22` B 波表位置，`23`–`34` A/B/C 的声源密度/位置/变形/弯曲 |
| `mod.N.amount` | −1…1 |
| `mod.N.bipolar` | 把单极性调制源重新居中到零 |
| `mod.N.curve` | −1…1，以线性为中心的整形指数 |
| `mod.N.slew_up`、`mod.N.slew_down` | 单极点上升/下降时间，单位为秒 |
| `mod.N.aux`、`mod.N.aux_invert` | 与路由深度相乘的第二个调制源：`0` 无，`1`–`29` 为上面的调制源编号加一；`aux_invert` 将其取反 |

引擎中还有四个调制目标没有数字编号，所以工程中的路由暂时无法使用它们：噪声电平、副振荡器电平、滤波器湿声和滤波器 2 湿声。目录把它们列为未映射，编辑器的目标菜单止于最后一个可用编号 `34`。

宏为 `macro.1` … `macro.8`。步进音序器有 `step.rate`、`step.sync`、`step.division` 和 `step.smoothing`。

效果架有自己的调制槽 `fxmod.N.*`，字段为 `source`、`parameter`、`fx_index` 和 `amount`。

## 合成器效果架

效果架位于各发声求和之后、输出级之前，最多容纳 16 个模块。

```ocp
params: {fx.count: 2,
         fx.1.type: delay, fx.1.mix: 0.3, fx.1.feedback: 0.35,
         fx.1.time: 0.375s,
         fx.2.type: reverb, fx.2.mix: 0.2, fx.2.decay: 2.4s}
```

- `fx.count` 设定链的长度。槽位从 1 开始计数。
- `fx.N.type` 是模块标签或其数字索引：`drive`、`compressor`、`eq3`、`delay`、`reverb`、`chorus`、`distortion`、`phaser`、`flanger`、`filter`、`utils`、`split`、`split3`、`split_ms`、`bode`、`parallel`、`hyperd`、`conv`、`multiband`。
- `fx.N.enabled`（0/1）旁通一个模块。
- 其他所有 `fx.N.<name>` 都是该模块的参数（`mix`、`drive`、`feedback`、`time`、`cutoff`、`width` 等）。
- `split`、`split3`、`split_ms` 和 `parallel` 把紧随其后的槽位作为子链。

只有设置了 `type` 的槽位才会创建模块。没有类型的槽位上的参数不起作用。

目录收录了全部 19 种模块类型。其中十种在编辑器中有专门的控件：`drive`、`compressor`、`eq3`、`delay`、`reverb`、`chorus`、`distortion`、`phaser`、`flanger` 和 `filter`。其余九种可以在效果架中运行，并保留音色补丁中存储的参数值，但编辑器暂时没有它们的控件。

## 预设导入 {#preset-import}

**加载**，以及振荡器页面上的 **导入预设** 操作，都会打开文件选择器，把一个外部预设文件导入当前工程预设。文件名成为工作台标题栏中的 `patch:` 来源标签。路径保存为 `serum_file`，所以重新打开工程时仍能看到源文件名。

导入器只读取一种外部预设格式：`.SerumPreset`，即一款波表合成器的预设格式。出厂音色库和用户库都不会经由这条路径加载。其他扩展名的文件会被拒绝，提示中会给出文件名和支持的格式。

导入属于整体加载，遵循与从浏览器加载相同的规则：

- 后端解析文件，把整个音色补丁作为工程参数返回。前端不做任何解析。
- 文件声明的每个值都会生效，包括其中的调制路由和内部效果架（`fx.N.*`）。
- 原音色补丁声明了而文件没有声明的参数会被移除，回到音色补丁默认值。工程预设的 `effects:` 链和 `patch:` 标签在同一个撤销步骤中被替换。
- `wavetable.file` 和 `open_synth_state_file` 会被清除，因为导入的波表来自源文件。
- 导入的文件不会被试听。只有成功的加载才会改变工程。如果文件格式不受支持、无法读取或无法解析，工作台会显示文件名和解析器给出的原因，预设保持不变。
- 文件选择器会在上次导入的文件夹中重新打开（该位置保存在本机）。第一次导入时，它打开在系统对话框的默认位置。

引擎在工程加载时映射这个预设，所以对于数值参数无法承载的状态，`serum_file` 始终是依据：自定义波表、采样层和琶音器。请把文件放在工程能找到的位置；文件被移动后，工程会报告加载错误。

映射的行为：

- 每个未映射的模块、参数和路由类别都会产生一条去重后的警告，不会被悄悄丢弃。未映射的类别包括颗粒和频谱振荡器的细节、部分扭曲模式、个别参数，以及需要超过效果架 16 个模块上限的预设。
- 有些控件有意不做映射：Bode 的 **Blur** 和 **Delay Balance** 控件、**Retrig**（位于发声之后的效果架收不到音符事件）、**Beat Sync**（效果架拿不到走带速度），以及部分多段压缩器控件。
- 按声源的总线发送会合并为最响的那一路，因为发声之后的效果架只有一路立体声总和。因此总线效果器处理的是全部发声的总和。
- 导入的调制路由使用中性的 `curve` 和 `slew` 默认值，因为导入器没有它们的换算规律。
- Utils 模块中间的 **wet** 位置使用通用的振幅交叉渐变。全湿和全干是精确的。

引擎侧的映射及其限制见[实用、分频与移频效果器](../../fx-utils-split-bode.html)（英文）。原创性政策见[兼容性与原创性](../../compatibility.html)（英文）。
