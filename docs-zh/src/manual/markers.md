# 标记与循环区域

标记为时间线上的一个点命名。循环区域是走带反复播放的排练窗口。两者存放在不同的地方：标记属于工程，循环区域属于播放会话。

## 标记

用 `@marker`、一个名称和 `at` 位置写出标记。位置与其他时间线位置一样，采用 `bar:beat:subdivision` 形式。

```ocp
@marker "Verse 2" at 9:1

@marker outro at 41:1:2
```

标记是工程数据。它们随工程保存和加载，出现在 DSL 文本中，`ocp fmt` 会按时间线顺序排列它们。没有标记的工程不会写出任何标记行。

标记只是时间线上的注释，不影响编排：

- 它可以放在最后一段音频之后。标尺会在那里显示它，编排不变。
- 它不会改变 `ocp render` 或导出的结果。
- 两个标记不能同名。校验器和标记命令会拒绝重复的名称，并指出已经使用该名称的标记。
- 小节或拍为 `0` 的位置会被拒绝，因为小节和拍从 `1` 开始。细分为 `4` 或更大的位置也会被拒绝，因为一拍只有 `0` 到 `3` 四个细分。

## 标尺上的标记操作

每个标记在标尺上显示为一面小旗，旁边是它的名称。

要在播放头处添加标记，按 `Alt+T`，或在标尺的右键菜单中选择 **在播放头添加标记**。只要加载了工程，这个命令就可用。新标记依次命名为 `Marker 1`、`Marker 2` 等；如果需要更有意义的名称，之后再重命名。

对已有的小旗：

- 单击，播放头移到该标记。
- 拖动，移动该标记。小旗跟随指针，松开指针时写入一条撤销记录，所以整个拖动在历史中只占一步。
- 双击，打开 **重命名标记** 对话框。名称为空时 **确定** 不可点击。webview 没有 `window.prompt`，所以这个对话框由应用自己绘制。
- 右键单击，弹出包含 **重命名标记…** 和 **删除标记** 的菜单。选择删除后会先询问 **删除标记？**，确认后才删除。

保存修改期间，标尺显示 `正在保存标记…`。保存失败时，标尺显示 `标记未保存：{reason}`。

## 循环区域

在标尺底边的窄条上拖动即可画出区域。区域显示为覆盖在标尺上的一条着色带，走带中的 **循环** 按钮（`L`）随之可用。

**循环** 按钮、`L` 键和标尺右键菜单中的 **循环该区间** 用来开启和关闭循环。只有存在区域时它们才起作用。在此之前按钮不可用，提示文字为 `先在标尺上拖出循环区间。`走带应用这次修改期间，标尺状态显示 `正在应用循环…`。

再次拖动窄条会重新画出区域，着色带跟随指针。窄条或标尺右键菜单中的 **清除循环区间** 会移除区域，走带确认后着色带消失。这些修改中任何一个失败时，标尺状态和走带都会显示 `循环未改变：{reason}`。

走带会拒绝短于一拍的区域，提示 `Loop region is shorter than one beat; drag a longer region or clear it.`它也会拒绝起点在工程结尾之后的区域，因为那里没有音频。起点在工程内、终点超出工程结尾的区域会在工程结尾处折返，标尺状态显示 `循环终点超出工程结尾；播放会在工程结尾处折返。`清除区域会关闭循环，所以按钮绝不会承诺一个无处可去的折返。

### 区域存放在哪里

循环区域是会话状态。应用把它连同开启状态一起，以工程路径为键存放在 webview 的本地存储中。它在重新加载和重启应用后仍然保留，但绝不会写进 `.ocp` 文件。

这样设计依据的规则是：控件必须如实反映重新加载之后会发生什么。

- 区域是排练辅助手段。它只改变播放，不改变其他任何东西，所以不放进别人也会打开的文件里。
- 本地存储会同时恢复着色带和开启状态。重新加载后你看到的就是播放实际的行为；不会出现着色带还在、循环却已悄悄关闭的情况。
- 不再适用的区域（例如工程变短了）会从屏幕上移除，标尺状态以 `循环未改变：{reason}` 显示后端给出的原因。
- 区域不是工程的一部分，而离线渲染器和导出只接收工程，所以区域影响不到它们。

### 播放

开启循环后，流式播放在区域终点处折返。折返使用普通的跳转路径：先排空剩余的预读，流跳回区域起点，再继续渲染。因此一次折返的开销与一次向后跳转相同。对于需要重建乐器的工程，循环点处可能出现短暂的空隙。不开启循环时，播放会穿过区域，一直播放到工程结尾。

区域画在流式走带所播放的写出时间线上，只受工程结尾的限制。如果循环已开启而播放头已经越过区域终点，按播放会跳回区域起点。

## 段落、重复与循环

`@section` 的重复只在离线渲染工程时展开，流式走带播放的是写出的时间线。循环区域折返的是走带播放的同一组写出位置，所以重复不会移动、复制或缩短它。开启循环也绝不会改变编排或渲染长度。

设想一个工程有一个重复的段落，循环区域靠近该段落的结尾。渲染出的编排比写出的长，如果按渲染后的结尾来定位区域，折返时就会落在不同的音乐上。因此循环按写出的四分音符定位，编排保持不变。测试 `section_repeats_do_not_move_a_loop_region` 固定了这一映射。

## 循环不影响的内容

渲染和导出会忽略循环区域。离线渲染器接收的是工程，而区域从来不属于工程，所以开启循环时两个门控测试样例的输出仍然逐字节相同。测试 `a_loop_region_does_not_change_the_offline_render` 固定了这一点，同时还有针对无标记工程的逐字节一致性测试。
