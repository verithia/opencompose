# 音频设备

应用中由一个所有者打开所有输出流和采集流。它保存两份设备列表、所选设备、协商后的采样率和周期、采集声道布局，以及已打开的流的健康状况。

## 音频页面

打开 [偏好设置](preferences.md)，选择 **音频**。最上面是输出控件，接着是采集控件，最后是 MIDI 输入。

| 控件 | 作用 |
|---|---|
| 输出设备 | 所有输出流打开的设备。**系统默认** 在每次打开流时跟随操作系统设置。 |
| 采样率 | 输出流应使用的采样率。渲染线程以流打开时报告的采样率运行，所以如果设备给出不同的答复，播放会停止并重建。 |
| 缓冲区大小 | 输出回调周期，以帧计。修改后会重新打开流，并保留走带位置。 |
| 延迟 | 只读：一个输出回调周期加上实时主输出效果链，以毫秒和帧显示。 |
| 输入设备 | 采集流打开的设备。**系统默认** 跟随操作系统设置。 |
| 输入声道 | **立体声**（默认）或 **单声道**。单声道设备在两侧都能听到；**单声道** 会把立体声设备缩混。 |
| 监听输入 | 把采集信号混入输出。默认关闭，因为麦克风经扬声器播放会产生反馈。 |
| 监听增益 | −24 dB 到 +12 dB，只在监听开启时生效。 |
| 输入电平 | 只读：最近一个采集块的峰值；一旦有采样达到满刻度，就显示削波标记。 |

选择器显示的是实际打开的设备，可能与你请求的不同。如果设备拒绝了你的选择，之前的设备保持打开，选择器回到它，页面会说明原因。如果设备不提供你选择的采样率，就打开它所提供的最接近的采样率，页面会写明是哪一个。流以协商请求之外的采样率打开时也是如此。

页面还会在以下情况给出提示：

- 已保存的设备未连接，正在使用系统默认设备；
- 设备自己控制周期，所以无法选择缓冲区大小；
- 请求的周期超出设备范围，已被截断；
- 后端拒绝了固定周期，正在使用设备周期；
- 已打开的流报告了后端错误；
- 设置文件无法读取或写入。

## 设备键

选择按后端保持稳定的键保存，绝不按显示名称保存。因此设备被改名，或出现另一个同名设备时，已保存的选择不受影响。输出设备和采集设备使用同一套方案。

| 平台 | 键 |
|---|---|
| macOS | CoreAudio 设备 UID（`kAudioDevicePropertyDeviceUID`），例如 `coreaudio:AppleUSBAudioEngine:…`。 |
| Windows | WASAPI 端点 id（`IMMDevice::GetId`），例如 `wasapi:{0.0.0.00000000}.{…}`。 |
| Linux | ALSA PCM 名称，例如 `alsa:default`、`alsa:hw:1,0`。 |

如果后端不提供稳定标识，键会退回到 `name:<display name>`，此时选择的稳定程度取决于名称。

## 输出协商

采样率列表来自设备自身支持的配置，并筛选为应用所打开的双声道流。主机 API 可能报告一个范围而不是一组采样率；遇到范围时，列表包含落在该范围内的标准采样率。

- 请求的采样率不在列表中时，打开最接近的可用采样率。距离相同时选较低的那个。
- 完全不报告任何配置的设备，退回到它自己的默认采样率。
- 请求的周期会被截断到设备报告的范围内。
- 不报告缓冲区范围的设备使用自己的周期，页面会说明这一点。
- 如果后端拒绝固定周期，会改用设备周期重新打开流，页面会显示被拒绝的原因。

渲染线程以流打开时报告的采样率运行。假设你请求 96 kHz，接口答复 48 kHz：页面会同时写出两个采样率，渲染线程保持 48 kHz，走带继续播放。之后的重建使用答复的采样率。如果设备答复的采样率与渲染线程当前运行的不同，渲染线程及其环形缓冲区会被丢弃，走带保持暂停，新的采样率随之生效。

## 采集格式

采集流请求输出协商确定的采样率，所以录音通常不需要重采样。如果采集设备提供的是其他采样率，就打开它最接近的那个，页面会同时写出两个采样率。采集默认以双声道打开。只有一个声道的设备会报告声道数减少，不会去请求它无法打开的布局。

打开页面不会打开采集。只有在你选择输入设备或布局、开启监听或准备录音时才会打开采集，详见 [偏好设置](preferences.md) 中的采集规则。监听时，单声道设备会复制到输出的两侧，立体声设备保持原有声像，**单声道** 会把它缩混。

## 监听与录音

监听信号通过一个无锁环形缓冲区混入输出回调，所以采集到的一帧会在下一个输出块中被听到。在 44.1 kHz 立体声下，这个环形缓冲区约能容纳 0.19 s。开启监听时会先清空环形缓冲区，所以你不会听到切换之前采集到的咔嗒声。

混音发生在输出流内部，所以只有在输出流打开时你才能听到监听。输出流在第一次播放或第一次试听时打开。

录音路径使用第二个环形缓冲区，大小为 96 000 个采样，由走带轮询取出。录音会把泵来不及取走的帧报告为 "frames were dropped because the take pump fell behind"。监听单独报告自己的丢失：当输出回调跟不上时，这些帧会被计数，较早的音频不会被覆盖。

录音会按应用自身产生的延迟平移录音：一个采集回调周期加上实时输出路径。音频视图把它报告为 `input_latency_frames`。音频录音会从所写文件的开头去掉这么多帧以及预备拍部分。数值的推导见 [播放延迟](../playback-latency.html)（英文）。

## 保存的设置

你的选择保存在 `~/.opencompose/audio.json` 中。文件以原子方式写入，使用与 `midi.json` 相同的私有文件写入器：

```json
{
  "output_device": "coreaudio:AppleUSBAudioEngine:…",
  "output_device_name": "USB Interface",
  "sample_rate": 48000,
  "buffer_frames": 256,
  "input_device": "coreaudio:AppleUSBAudioEngine:…",
  "input_device_name": "USB Interface",
  "input_channels": "stereo",
  "input_monitor": false,
  "input_monitor_gain_db": 0.0
}
```

`null` 对设备表示系统默认，对采样率和周期表示设备默认。每个键旁边都保存了显示名称，这样即使设备缺失也能写出它的名字。

如果启动时已保存的设备不在，会打开系统默认设备。页面会写出缺失设备的名称，并保留它的键。重新连接设备后，按刷新按钮（↻，**刷新音频设备**）。已保存的选择会恢复，已打开的流也会切回该设备。

[偏好设置包](../preferences-bundle.html)（英文）可以把同样的选择带到另一台电脑上。

## 流的健康状况

如果输出流的后端报告错误，走带会暂停并显示 `Audio output stopped: …`，音频页面会把这次故障作为提示保留。没有正在运行的输出流时，走带绝不会显示为 *播放中*。

如果采集流报告错误，已准备的录音会停止。已经送达的帧会被保留，录音会说明停止的原因。音频页面会把采集故障作为输入提示保留，直到下一次成功打开。

## 限制

没有热插拔检测，输出和输入都没有。音频主机层没有断开事件，macOS 默认设备流也不安装移除监听器。设备消失后，要通过错误回调或下一次枚举才会被发现。采集设备在请求采集时才会被枚举，所以之后插入的麦克风要刷新后才会出现。没有任何机制会自动跟随系统默认输入。因此页面提供了明确的刷新按钮，不会自行重新连接。

只支持立体声。每个输出流都以两个声道打开，采集最多打开两个声道。不支持多声道接口、声道映射，以及输入或输出超过两个声道的聚合设备。

没有独占模式。所有输出都与系统混音器共享。不支持 CoreAudio 独占（hog）模式、WASAPI 独占模式，也没有 ALSA `hw` 路径。

监听依赖输出流。走带停止时采集路径仍在运行，但只有在输出流打开时你才能听到监听信号。如果启动应用后直接开启监听，在播放或试听打开输出之前都不会有声音。

Windows 和 Linux 只经过编译检查。CoreAudio 键查找在 macOS 上运行过。WASAPI 端点查找和 ALSA PCM 键能够通过编译，但尚未在这些系统上运行。

## 验证

无界面测试使用一个假设备后端。在输出方面，它们涵盖选择、持久化、回退、采样率与周期协商、打开失败、流失效以及对已打开流的清理。在采集方面，它们涵盖按需打开、监听混音及其增益、电平表与削波锁存、失效的采集流，以及答复了与协商请求不同采样率的设备。

真实的流打开、回调大小、硬件延迟、设备移除和采集路径需要以下手动测试矩阵：

1. macOS，使用内置输出和一个 USB 接口：在播放时双向切换，拔下接口，重新连接并刷新。
2. Windows，使用一个 48 kHz 端点：以 44.1 kHz 打开设备，检查页面显示的是实际打开的采样率。
3. Linux，ALSA `default` 分别经由 PipeWire 和 dmix 路由：检查选择器中出现 PCM 名称，并且缓冲区范围得到遵守。
4. macOS，使用内置麦克风：准备录音并说话。检查电平表有变化，走带至少运行过一次后能听到监听，并且录音落在节拍器标出的拍上。
5. 只有一个输入的 USB 接口：选择 **立体声**，检查页面报告了声道数减少；再选择 **单声道**，检查采集能够打开。
6. 在已准备的录音进行时拔下采集设备。录音停止，已经采集到的音符和帧被保留，页面写出消失的设备名称。
