# 自动化 {#automation}

自动化轨道是一串“位置/数值”点，按工程时间求值。自动化轨道有三种形式，区别在于驱动的对象：

| 形式 | 所属 | 驱动 | 精度 |
| --- | --- | --- | --- |
| `automation:` 控制自动化轨道 | 轨道 | 轨道乐器的某个乐器控制或宿主参数 | 解释器输出的事件流 |
| `automation:` 效果器自动化轨道 | 轨道、总线、主输出 | 该所属对象效果链中某个效果器的一个参数 | 按音频块的图包装器 |
| `gain_automation:` 片段 | 轨道、总线、主输出 | 插入效果之后的线性增益 | 采样级精确的增益级 |

带作用范围的 `automation:` 片段可以写 `playlist_lane=3`，在播放列表第 3 行显示。`gain_automation:` 片段在时间区间之后接受同一个属性。片段仍然属于原来的轨道、总线或主输出。

本页主要讲效果器自动化轨道。控制自动化轨道见 [.ocp 文件](manual/dsl.md)，增益片段见[混音器路由](mixer-routing.md)。

## 插入效果控制 {#insert-controls}

每个轨道、总线和主输出的插入效果都有自己的湿声比例，从 0 到全湿。在效果器声明中用 `slot/wet` 设置初始比例。自动化轨道可以用归一化数值或百分比驱动同一个控件。插入效果把效果器输出与经过延迟对齐的输入副本混合，所以设备自己的 Mix 参数仍可单独调节。

```ocp
@bus motion
  effects:
    - gain: factor=2, slot/wet=25%, bypass=true
  automation: fx1.slot/enabled {1:2=true, 3:1=false}
  automation: fx1.slot/wet {1:2=25%, 2:1=100%}
```

开关自动化轨道把每个开关值保持到下一个节点。带动画的插入效果在输出干声时仍让设备运行，这样既保留设备的历史状态，开关切换时延迟补偿也保持不变。静态的 `bypass=true` 如果没有生效的开关自动化轨道，设备不会加载。

## 紧凑的指数段 {#compact-exponential-segments}

一段曲线可以存储它的解析曲率，而不是一长串线性采样。系数属于该段的起始节点：

```ocp
@bus motion
  effects:
    - gain: factor=1
  automation: gain.factor {1:1=0.2 curve=exponential curvature=-4, 3:1=0.8}
```

对 `[0,1]` 内的进度 `u`，形状为 `E(k,u) = expm1(k*u) / expm1(k)`。`k=0` 时恰好等于 `u`。正系数向终点加速，负系数提前移动。有限的系数范围由参数表决定，目前为 `[-64,64]`。原有的 `smooth` 曲线及其 `tension` 含义不变。省略曲率即为 0；在其他曲线上给出曲率是无效的。

镜像指数曲线用三个节点：两端各一个，中点一个。前半段系数为 `k`，后半段为 `-k`。把一段指数曲线截取到其中的 `[a,b]` 部分是精确的：使用采样得到的端点值和系数 `k*(b-a)`。跨过镜像中点的裁剪会保留该中点。不需要存储相位窗口，也不需要稠密近似。源格式导入器在存储这些段之前，必须先换算进出节点的约定。

效果器自动化轨道和编码后的托管乐器参数自动化轨道支持指数段，其他乐器/MIDI 自动化轨道会拒绝。`gain_automation:` 片段需要下文所述的显式 `segments` 插值；旧的 `linear` 和 `step` 增益模式保持原有行为。

### 显式不连续点 {#explicit-discontinuities}

包络或重复的 LFO 自动化轨道可以在节点之前声明 `discontinuities`。位置相同的节点保持书写顺序：第一个是前一段的左极限，最后一个是该采样上写入的值。这样无需另加一条自动化轨道或虚构一个一 tick 长的斜坡，就能存储瞬时跳变。渲染器在恰好落在该位置的采样上取最右边的节点，绝不会除以长度为零的段。不加这个标志时，原有行为不变。用重复的自动化轨道存储一个周期的节奏增益：

```ocp
@bus rhythm
  effects:
    - gain: factor=1
  automation: fx1.factor [1:1 - 9:1] mode=lfo speed=1/2 discontinuities {1:1=1, 1:2=0, 1:2=1, 1:3=1}
```

这里每个二分音符都重复同样的渐变和跳变。只要改一次周期中的四个节点，就能改变节奏。周期跟随速度变化，定位时保持同一相位。片段结尾处的独占重置仍需在该边界显式写入；这个标志不会延长片段的写入范围。

自动化 Gain 设备的 `mix` 可以单独改变周期的深度。`mix=0` 时输入原样通过，`mix=1` 时应用完整增益，中间值在两者之间线性混合。Gain 默认是完全混合，所以已有工程的电平不变。

### 解析式的插入后增益片段 {#analytic-post-insert-gain-clips}

`gain_automation: segments` 显式地为插入后的增益级选用同一个预先准备的分段求值器。已有的 `linear` 和 `step` 片段保持旧的解释，并拒绝映射和不连续标志。

```ocp
@bus level
  gain_automation: segments ppq=48 [1:1 - 3:1] discontinuities mapping(exponential, curvature=2, input_quantization_steps=128) {1:1=0.2 curve=exponential curvature=-3, 2:1=0.8, 2:1=0.4, 3:1=1}
```

片段在插入效果之后、独立的静态推子之前乘到音频上，在其独占范围之外返回单位增益。片段范围之外的原始节点仍作为插值上下文，不产生额外写入。没有映射时，数值节点是物理线性增益；有映射时，它们是接收端的原始输入，映射结果必须落在增益所属对象的范围内。这个范围由设备目录决定。触摸仲裁、定位和音频块划分的语义不变，也不会准备稠密的控制点表。

### 数值接收映射 {#numeric-receiver-mappings}

可选的 `input_quantization_steps=N` 在传递之前把输入映射为 `floor(value*N)/N`。参数表允许 1 到 1,000,000 的正整数步数。负输入按数学下取整，不做钳制。准备阶段会拒绝非有限的乘积，以及变换后超出目标范围的值。省略这个字段即为原来的连续输入行为。

效果器自动化轨道可以在插值和 LFO 深度之后应用一次紧凑的数值传递。传递在自动化轨道的平滑器运行之前，产生接收端单位的值。

```ocp
@bus blend
  effects:
    - gain: factor=1
  automation: gain.factor mapping(linear, scale=-1, offset=1) {1:1=0, 3:1=1}
```

`mapping(linear, scale=s, offset=o)` 计算 `o+s*v`。`mapping(exponential, curvature=k, scale=s, offset=o)` 计算 `o+s*E(k,v)`。默认是线性、零曲率、单位缩放和零偏移。负缩放适用于互补控制；零缩放是有效的常数传递，但无法被拖动节点的手势反推。

带映射的自动化轨道要求无单位的数值节点，接收端必须是效果器。曲线对原始节点插值，然后应用映射，得到 Hz 或 dB 等值。准备好的曲线会按接收端的范围检查映射后的有限极值，包括 LFO 深度。参数表限定指数的参数范围，溢出或不支持的输入会报错。

拆分带映射的自动化轨道时，会采样**未映射**的接缝节点，两半都保留映射。指数系数按每一半所占的比例截取，所以映射只应用一次。时间仍由 ProjectClock 的采样量化决定，不会引入任意的时间偏移。带区间的片段仍在独占的终点停止写入；同一采样位置上的多个节点保留最后书写的那次写入，而不会生成一段虚构的插值斜坡。

## 效果器自动化轨道 {#effect-lanes}

```ocp
@track bass | instrument: synth/bass
  effects:
    - compression: threshold=-18dB, ratio=4
    - plugin:"vst3.MyCompressor"
  automation: compression.threshold {1:1=-24dB, 3:1=-6dB}
  automation: fx2.Mix [ppq=480] smoothing=25ms {1:1=50%, 5:1=80% curve=smooth}

@bus drums
  effects:
    - eq: mid_freq=1kHz
  automation: eq.mid_freq {1:1=800Hz, 9:1=3000Hz}

@master
  effects:
    - limiter: ceiling=-1dB
  automation: limiter.ceiling smoothing=10ms {1:1=-3dB curve=stairs, 7:1=-1dB}
```

自动化轨道可以带一个 `smoothing=` 时间。每个节点可以带一个 `curve=`，`curve=smooth` 的节点还可以带 `tension=`。默认平滑为 0 ms，曲线为 `linear`。节点的 `curve` 决定从该节点到下一个节点这一段的形状。`stairs` 会保持数值直到下一个节点。

自动化轨道的名字是 `<效果器>.<参数>`。效果器有两种寻址方式：

- 按类型名：`compression`、`eq`、`limiter`、`stereo_width`、`ducked_send`、`plugin` 等，即 DSL 类型的下划线形式。只有效果链中恰好有一个该类型的条目时才能这样写。有两个压缩器时，`compression.threshold` 有歧义。
- 按从 1 开始的效果链位置：`fx2` 是所属对象 `effects:` 列表中的第二项。类型重复时用这种写法。要在多个插件中指定其中一个，只能用这种写法。

自动化轨道寻址的是所属对象自己的 `effects:` 列表。来自预设的效果器无法从轨道寻址，预设本身也不带自动化。

对内置效果器，参数必须是该设备参数表中的参数 id（`ocp devices list` 会打印出来）。数值按设备自己的单位和范围校验，与 `effects:` 条目中的同一参数相同。对插件效果器，参数名由插件匹配，忽略大小写和标点；数值按插件的原始取值域传递，与 `effects:` 条目所用的取值域相同。不存在或不可自动化的插件参数不会产生任何变化。

### 移动延迟的读取位置 {#moving-delay-read-positions}

希望时间曲线连续扫过延迟缓冲区时，在延迟上开启 `interpolate=true`。这适用于磁带减速、音高扫频，以及在输入循环的前几拍之间移动。要让立体声联动，把两个声道设成同一条曲线；只想重放输入时，把反馈设为零。例如：

```ocp
@bus motion
  effects:
    - delay: time_l=1ms, time_r=1ms, feedback=0%, mix=100%, interpolate=true
  automation: fx1.time_l {1:1=1ms, 1:2=126ms}
  automation: fx1.time_r {1:1=1ms, 1:2=126ms}
```

延迟最多保存两秒音频。抽头之间的跳变在音频中也是跳变，所以需要平滑过渡时，请用一段短斜坡。单独的节奏电平曲线请用 `gain_automation:`。已有的延迟设置默认仍使用整数采样抽头。

要做速度同步的回声，设置 `tempo_sync=true`，并以四分音符的分数写 `quarters_l` 和 `quarters_r`。抽头跟随速度变化，每个抽头最多两秒。没有走带时使用的延迟按 120 BPM 计算。

```ocp
@bus echoes
  effects:
    - delay: tempo_sync=true, quarters_l=0.75, quarters_r=0.75, routing=ping_pong, feedback=45%, feedback_filter=low_pass, feedback_cutoff=2400Hz, mix=100%
```

Stereo 保持两个声道独立。Mono 在两个抽头之前把输入取平均。Swapped 交换两路湿声输出。Ping Pong 交换反馈声道，所以第一次回声留在输入所在的一侧，之后的回声左右交替。反馈滤波器在第一个抽头之后塑造后续回声。`dry_gain` 和 `wet_gain` 分别缩放 Mix 的两路输出。要分别设定干声和湿声电平，从 `mix=50%` 开始，把每个增益设为期望输出电平的两倍。

## 时间与取值域 {#time-and-value-domain}

节点使用与控制自动化轨道相同的位置写法：`bar:beat:subdivision`，或 `[ppq=N]` 的 tick 位置。每一段从一个节点到下一个节点按其曲线变化。没有时间区间的自动化轨道（整条时间线形式）在第一个节点之前保持 `effects:` 中声明的值，在最后一个节点之后保持最后的值。构建音频图时，每个节点都会编译成绝对采样位置。

| `curve` | 在 0..1 内位置 `u` 处的分段值 |
| --- | --- |
| `linear`（默认） | `y0 + (y1 - y0)·u` |
| `stairs` | `y0`（在下一个节点处跳变） |
| `half_sine` | `y0 + (y1 - y0)·(1 - cos(πu)) / 2` |
| `smooth` | `y0 + (y1 - y0)·(u + t·(3u² - 2u³ - u))`，`t` = `tension`，取 0..1（默认 1） |

数值在每个采样上按公式计算，不查表。自动化轨道的 `smoothing=` 会在目标值上加一个单极点低通：

    y[n] = a·y[n-1] + (1 - a)·target[n],   a = exp(-1 / (smoothing_s · sample_rate))

因此在任何采样率下，阶跃都会在 `smoothing_ms` 内到达其高度的 63.2 %。平滑器从绝对采样位置逐个采样推进，与音频块边界无关，所以同一个工程以 64 帧和 512 帧渲染，得到的数值相同。定位时，平滑器会在目标值上重新初始化，与下文所述的重新应用数值相同。

渲染按音频块进行：

- 插件效果器（VST3/CLAP）通过 MIDI 参数路径所用的同一个 `pending_events` 队列，以带块内相对采样偏移的参数变化，收到块内每一个变化的值。在从采样 0 开始的 512 帧块中，位于 `1:1:2` 的节点落在偏移 100 处，位于块内部。
- 内置设备没有事件队列。音频块会在每个数值与前一个采样不同的位置拆分，并在每个拆分点调用 `set_param`。不带平滑的 `stairs` 自动化轨道只在节点处拆分。连续曲线或平滑过渡会逐采样拆分。
- 定位或重置时，会重新应用自动化轨道在新位置上的值，所以从时间线中间恢复的自动化轨道不会留下过时的参数。
- 插件收到的分块不超过其处理上限，并且在速度和拍号变化处拆分，所以队列中的每个偏移都落在设备即将处理的块内。

包装器原样报告被包装效果器的延迟、尾音、侧链和电平表，所以插入效果链的延迟补偿和电平表不受影响。

## 自动化片段 {#automation-clips}

自动化轨道可以带一个时间区间。带区间的自动化轨道就是片段：节点列表和曲线规则不变，但在时间上有位置和边界。不带区间的自动化轨道覆盖整条时间线。

```ocp
@track bass | instrument: synth/bass
  effects:
    - compression: threshold=-18dB, ratio=4
  automation: compression.threshold [3:1 - 5:1] {4:1=-24dB, 4:4=-6dB}
  automation: fx1.Mix [3:1 - 5:1] muted {3:1=100%, 5:1=60%}
```

区间写作 `[start - end]`，与段落、片段和 `gain_automation:` 的范围语法相同，终点不包含在内：`[3:1 - 5:1]` 写入第 3 和第 4 小节。`muted` 是不带值的标志，与 `gain_automation:` 上的 `linear` 和 `step` 一样。它写在区间之后，让整条自动化轨道静音。片段仍可带可选的 `[ppq=N]`、`mode=`、`smoothing=` 和周期控制，在序列化形式中写在区间之后。

### 片段写入什么 {#what-a-clip-writes}

区间决定何时写入，节点列表决定写入什么。

要导入已经录下的控制信号，在带作用范围的效果器自动化轨道上使用 `mode=recorded`。它的数值采样驱动与包络相同的插值。时间线把信号画成曲线，并作为片段保持可编辑，但单个采样没有节点编辑控件。

- 区间之前，自动化轨道不写入，参数保持其 `effects:` 条目中声明的值。
- 区间内、第一个节点之前，保持第一个节点的值。节点从片段开头之后才开始的片段，一开始就是这个值。
- 区间内、最后一个节点之后，保持最后的值。
- 区间结束时，自动化轨道停止写入。最后写入的值留在参数上：片段写入后保持，不会回退。
- 静音的自动化轨道在任何位置都不写入，参数处处保持声明的值。
- LFO 自动化轨道的周期从片段开头开始，开头可能早于第一个节点。波形在开头处按相位重新开始，重复的片段不会继承上一遍的相位偏移。节点仍描述一个周期，形状不变。

这条释放规则与 `gain_automation:` 有意不同。增益片段在范围之外回到单位增益，因为单位增益是混音级为它声明的值。截止频率、压缩比或干湿比如果跳回声明值，会产生听得见的跳变，所以自动化片段让参数停在片段结束时的位置。可以把增益片段看作增益级，把自动化片段看作参数位置。

节点可以位于区间之外。它在那里不写入，但仍影响区间内的曲线。开头之前的节点决定开头处的插值，终点之后的节点会把最后一段拉向它的值，即使自动化轨道在终点就停止写入。

同一个 `(owner, target)` 上的两条自动化轨道不能同时写入。同一目标上的片段不能重叠，片段也不能与整条时间线的自动化轨道共用目标。片段可以首尾相接。规则和报错信息见[校验](#validation)。

## 读回自动化轨道的值 {#reading-a-lane-back}

`oc_dsl::automation::value_at` 是唯一的求值器。它按工程时钟编译自动化轨道的节点，返回某个四分音符位置上的值，涵盖四种曲线、逐节点张力、LFO 相位及其周期控制。凡是自动化轨道不写入的地方，它都不返回值：静音的自动化轨道、整条时间线自动化轨道的第一个节点之前，以及片段区间之外。渲染器采样同一份曲线代码。只有单极点平滑器和 LFO 的采样时钟有状态，它们留在渲染器中。所以自动化轨道的 `smoothing_ms` 作用于渲染器的输出，`value_at` 返回的是未经平滑的目标值。

图形界面通过 `automation_value_at(target, lane_param, lane_index, position_beats)` 读取。该命令返回以下两者之一：

- 被驱动的值，使用效果器自己的单位；音色或托管插件的自动化轨道则返回 0..1 的归一化位置；
- 没有自动化轨道驱动该控件的原因：目标没有自动化轨道、参数对应多条自动化轨道、所属对象被静音、自动化轨道被静音、走带停止，或播放头不在自动化轨道写入的范围内。

没有被驱动的值时，面板显示保存的值。被驱动的控件会带一个标记和一个虚线圈，自动化轨道停止驱动或你拖动该控件时，它们会消失。

## 写入自动化 {#writing-automation}

**写入自动化**是工具栏 **走带设置** 弹出面板中的一个开关。同一个操作也是命令注册表中的命令，所以可以重新绑定快捷键，也可以在命令面板中运行。整个会话只有这一个开关。OpenSynth 编辑器、设备架上的旋钮和托管插件的参数面板都读取它。它是会话状态，不会写入工程、DSL 或保存的文件。

开关打开后，拖动旋钮会记录一条曲线：

- 走带运行时，写入器在每次走带轮询（约 20 Hz）和每次指针移动时取一个样，再把每个样吸附到时间线网格上。每个网格单元保留最后落入其中的值。按住旋钮不动会记录一条水平线，慢慢移动会记录一条曲线。
- 走带停止时，同样的手势在播放头处写入一个节点。
- 按下但没有改变参数的操作不写入任何内容。

采样受轮询频率限制。节点位置以 `bar:beat:subdivision` 存储，所以可写入的最小步长是十六分音符。在 120 bpm 下，一个十六分音符长 125 ms，而轮询间隔是 50 ms，所以 1/16 网格以及更粗的网格都能完整填满。在更细的网格（1/32、三连音）上，每个样会取整到最近的可存储单元，即十六分音符，所以自动化轨道得到的是最近的真实样本，中间不会凭空插值。

一次拖动是一个撤销步骤，标签为 `write automation`，无论写入了多少个节点。没有写入任何节点的拖动不会产生撤销步骤，也不会把工程标记为已修改。

参数还没有自动化轨道时，第一个节点会创建一条，按效果链位置寻址（`fx<N>.<param>`）。所属对象无法自动化的参数（预设效果链、没有数值范围的参数，或属于托管插件的效果链条目）会被拒绝，并给出设备参数表的说明，拖动则作为普通编辑执行。

手势结束后，状态栏报告结果。中文界面显示的是对应译文，例如“已记录 12 个点：filter.cutoff（1/16 网格）。”：

```
Recorded 12 points on filter.cutoff (1/16 grid).
Recorded 1 point at 3:2:3.
Nothing was recorded: automation write is off.
```

## 自动化轨道的标识 {#lane-identity}

同一个所属对象可以在同一个目标上有多条自动化轨道，所以自动化轨道由 `(owner, lane_param, lane_index)` 标识。图形界面中的每个编辑命令都接受可选的轨道索引。不给索引时，参数必须只对应一条自动化轨道。对应两条的参数会被拒绝，报错为 `Automation target 'filter.cutoff' has
2 lanes (0, 1); pass a lane index to choose one`，所以不会误改第一条。`automation_value_at` 遵循同样的规则，并以这句话作为原因。在区间功能出现之前就有的命令保持原有签名，同样拒绝有歧义的参数。

## 时间线上的自动化行 {#the-timeline-row}

在轨道菜单中选择 **显示自动化**，即可在该轨道下展开自动化行。总线和主输出的自动化轨道显示在最后一条轨道的自动化轨道之后，位于一条标明所属对象的横条下方，因为这些对象没有轨道头。一行会显示所属对象的全部自动化轨道，包括效果器、音色和控制自动化轨道，并标明目标类型，所以 `pluginparam_…` 这样的名字会显示为它所编码的参数。

在自动化行中编辑节点：

- 双击，在吸附后的位置添加一个节点。
- 拖动节点，可在两个方向上移动；虚影显示新位置。
- 按 `Delete` 删除选中的节点。
- 打开节点菜单，选择四种曲线之一或设置张力。

每个操作都是一个命令、一个撤销步骤。拖动只在松开时写入一次。设置了 `muted` 的自动化轨道会拒绝以上所有编辑，并提示 `该轨道已被静音。`你可以把节点移到区间之外，因为区间只限制何时写入，区间外的节点仍影响曲线。

自动化行的纵轴是目标可接受的范围。第一个节点可以放在范围内任意位置，拖动到边缘时会停住。效果器自动化轨道从设备参数表读取范围，`pluginparam_` 自动化轨道从音色参数表的物理取值域读取，`volume` 或 `pan` 自动化轨道读取混音器自己的增益或声像范围。没有已知范围的目标（例如托管插件，或设备参数表中没有列出的控件）按自动化轨道中现有的节点缩放。

自动化行菜单中的 **删除** 和设备架上自动化轨道行的 **删除自动化轨道** 按钮都调用 `remove_automation_lane`，所以任何自动化轨道都能删除，无论有没有区间。删除正在播放的自动化轨道，会把它从下一个音频图中移除，撤销可以恢复。

### 片段手势 {#clip-gestures}

在时间线的自动化行上，你可以移动、缩放、复制、拆分和删除片段块。每个手势都是一个命令，以所属对象（`track:N`、`bus:name`、`master`）、自动化参数和轨道索引为键，并且都是一个撤销步骤。每个命令在发布前都会重新校验。无法通过校验的结果绝不会被采用，拒绝时给出校验器自己的报错信息。

| 命令 | 含义 |
|---|---|
| `move_automation_clip(owner, lane_param, lane_index, to)` | 把区间和每个节点平移同一个量 |
| `resize_automation_clip(owner, lane_param, lane_index, edge, to)` | 把一侧边缘移到 `to`，另一侧不动 |
| `duplicate_automation_clip(owner, lane_param, lane_index, at)` | 把区间和节点复制到 `at` 处或之后的第一个空位 |
| `split_automation_clip(owner, lane_param, lane_index, at)` | 在 `at` 处把片段一分为二 |
| `delete_automation_clip(owner, lane_param, lane_index)` | 删除这条片段自动化轨道 |
| `remove_automation_lane(owner, lane_param, lane_index)` | 删除一条自动化轨道，无论有没有区间 |

各手势的规则：

- 移动：区间和每个节点平移同一个量，曲线形状和节点顺序都不变。如果新区间会与同一目标上的其他自动化轨道重叠，移动会被拒绝，报错信息给出两个区间。
- 缩放：移动一侧边缘，另一侧边缘和所有节点保持不动。会越过另一侧边缘或与其他自动化轨道重叠的缩放会被拒绝，并说明原因。节点不会被改写，所以缩小后落在区间外的节点仍影响区间内的曲线，与任何书写在区间外的节点一样。
- 复制：把区间长度、节点、静音标志和曲线控制复制到同一目标上的一条新自动化轨道，所有节点平移同一个量，并追加到所属对象的自动化轨道列表末尾。请求的位置被占用时，会越过每个阻挡的片段向右查找。如果在请求位置之后 64 小节内没有空位，或另一条自动化轨道在整条时间线上驱动该目标，复制会被拒绝，报错信息给出这个查找范围。
- 拆分：位置必须严格位于区间内，且距两侧边缘至少一个网格步长（十六分音符）。两半都保留每一个原始节点、单位和系数，包括位置相同的节点，只有区间改变。左半部分的区间在接缝处结束，右半部分从接缝处开始，所以在任何采样率下、经过速度变化，每个采样的值都不变，接缝处也不会新增节点。落在某一半区间之外的节点仍影响它的曲线。右半部分紧跟在左半部分之后插入。如果移动某一半会把它的某个节点推到工程开头之前，移动会被拒绝，不做任何改动；不会丢弃或重新采样节点。波形（`mode=lfo`）自动化轨道会被拒绝：拆开后每一半都会从自己的开头重新开始周期。
- 删除：删除带区间的自动化轨道。整条时间线的自动化轨道不是片段，片段手势会拒绝它并说明原因。要删除它，请用 `remove_automation_lane`，它可以删除两种形式，并且是一个撤销步骤。
- 五个手势都会拒绝使用自己 tick 网格（`[ppq=N]`）的自动化轨道。手势基于工程的记谱网格，而 tick 网格自动化轨道以 tick 存储位置。

## 校验 {#validation}

`ocp validate` 和 `oc-dsl` 校验会拒绝以下自动化轨道：

- 指向所属对象效果链中不存在的效果器（报错信息列出效果链中的效果器）；
- 类型名匹配多个条目（请用 `fx<N>`）；
- 效果链位置超出列表；
- 指向的内置设备没有该参数（报错信息列出参数 id）；
- `smoothing=` 超出 0..60000 ms，或 `tension=` 没有配合 `curve=smooth`，或超出 0..1；
- 在纯控制自动化轨道上使用曲线或平滑，因为 MIDI 控制自动化轨道是一串事件步进（内置音色参数自动化轨道在节点之间线性渐变）；
- `[start - end]` 区间的终点不在起点之后；
- 同一个 `(owner, target)` 上的两条自动化轨道同时写入。

两个片段的区间相交即为重叠。片段与整条时间线的自动化轨道总是重叠，因为后者没有终点。仅首尾相接的片段是允许的：`[1:1 - 3:1]` 和 `[3:1 - 5:1]` 在 `3:1` 处交接。报错信息给出目标和两个区间，整条时间线的自动化轨道表述为“over the whole timeline”。

`muted` 自动化轨道与其他自动化轨道一样校验。它的区间、节点、曲线规则和重叠都按未静音的情况检查。

插件参数名在插件加载之前是未知的。校验时接受它们，在效果器处理音频时再解析。

## 限制 {#limits}

- 内置设备上的连续曲线每个采样都设置一次参数，所以比 `stairs` 自动化轨道开销更大。逐采样拆分保证渲染精确，且与块大小无关。
- 自动化轨道的位置是时间线位置，不针对插入效果自身的延迟做补偿。前视（look-ahead）设备在变化到达它时才应用。
- 预设效果器和乐段效果器无法寻址。乐段效果器本身就会作为乐段内容被拒绝。
- 效果器自动化轨道不导出到 MIDI，也不产生乐器事件。
- 控制自动化轨道导出 MIDI 时会写出所有书写的节点，忽略片段区间和 `muted` 标志。因此静音或带区间的控制自动化轨道导出的控制器事件与整条时间线的自动化轨道相同。
- 只有时间线提供片段手势。面向智能体的命令、MIDI 导出和设备架都不会移动区间。`[ppq=N]` 自动化轨道和波形自动化轨道没有片段手势，见[片段手势](#clip-gestures)。
- 复制根据它看到的自动化轨道列表预留位置，所以同时运行的两次复制可能选中同一个空位。校验器会拒绝第二次复制。工程保持有效，第二份不会写入。

## 控制链接 {#control-links}

控制链接把一个控制源连接到多个参数。控制源可以是 MIDI CC、OpenSynth 宏或自动化轨道。每个目标都有自己的映射公式和平滑时间。

```ocp
@control_link drive
  from: cc(74)
  -> track: lead param: filter.cutoff formula: midi_unit smoothing: 8ms
  -> track: lead param: output.gain formula: exponential
```

`from:` 接受三种来源：

- `cc(controller[, channel])`，通道从 1 开始，默认为 1；
- `macro(index, preset)`，某个命名 OpenSynth 预设的第 1 到第 8 个宏；
- `lane(track, param)`，读取一条已注册自动化轨道的归一化值。

目标指定一个 `track` 和一个 `param`。`param` 是引擎参数键或托管插件参数名；含空格时要加引号。`smoothing:` 可选，单位为毫秒。

在自动化轨道链接中，`param: fx1.ParameterName` 指向混音器上的效果器，`track:` 给出拥有它的轨道或总线。例如，一段录下的动作可以同时驱动两条并行返回总线上的插入效果：

```ocp
@control_link echo_feedback
  from: lane(feedback_control, "fx1.factor")
  -> track: echo_left param: fx1.Feedback formula: linear
  -> track: echo_right param: fx1.Feedback formula: linear
```

目标收到的值位于其效果器的自动化范围内：托管效果器为 0 到 1。对使用物理单位的内置参数，加上与自动化轨道相同的 `mapping(...)`。映射在公式之后、目标平滑之前运行。下面这个链接覆盖 EQ 的整个频率范围：

```ocp
@control_link brightness
  from: lane(brightness_control, "fx1.factor")
  -> track: return param: fx1.high_cut_freq formula: linear mapping(exponential, curvature=6.907755278982137, scale=19980, offset=20)
```

一个目标只能接受一个链接或它自己的自动化，不能两者兼有。音频图会检查映射后的范围，并拒绝第二个写入者。

桌面端播放时，来自 MIDI 输入的 CC 可以驱动同样的混音器控件。这里通道 2 上的 CC 74 在提高 `lead` 第一个插入效果增益的同时，降低 `return` 上的增益：

```ocp
@control_link crossfade
  from: cc(74, 2)
  -> track: lead param: fx1.factor formula: midi_unit
  -> track: return param: fx1.factor formula: inverted
```

命名的 OpenSynth 预设可以保存一个效果架的控件。链接读取预设保存的宏，包括继承的值和音色文件：

```ocp
@preset RackControls
  source: builtin
  plugin: "builtin.open_synth"
  params: {macro.8: 0.25}

@control_link feedback
  from: macro(8, RackControls)
  -> track: echo_left param: fx1.Feedback formula: linear
  -> track: echo_right param: fx1.Feedback formula: linear
```

要改变数值，编辑该预设或其 `params:` 中的宏。对随时间变化的控制，请用 `lane(track, param)` 来源。不带预设的 `macro(index)` 链接仍可加载，并保持原有写法。

单目标写法 `target: track: ...` 仍然可以解析，加载为只有一个目标的链接。JSON 中的 `target` 字段也会以同样方式合并进 `targets`。

### 公式 {#formulas}

公式取自一组固定的名称，每个名称都有明确的映射。所有结果都会钳制到 0..1 的归一化参数域。

| 名称 | 输入 | 映射 |
| --- | --- | --- |
| `linear` | 归一化 0..1 | `y = x` |
| `inverted` | 归一化 0..1 | `y = 1 - x` |
| `exponential` | 归一化 0..1 | `y = x²` |
| `logarithmic` | 归一化 0..1 | `y = √x` |
| `midi_unit` | 原始值 0..127 | `y = raw / 127` |
| `midi_centered` | 原始值 0..127 | 在 64 处达到峰值的三角形：以下为 `raw/64`，以上为 `(127 - raw)/63` |

`midi_unit` 和 `midi_centered` 读取控制器的原始值，所以 `ocp validate` 会拒绝把它们用于宏或自动化轨道来源。其他四个读取控制源的归一化位置，对 CC 来说就是 `raw / 127`。

### 平滑 {#smoothing}

每个目标各自用一个单极点滤波器平滑。效果器自动化轨道链接在来源自动化轨道的平滑和目标公式之后，逐采样移动目标：

```
coefficient = 1 - exp(-frames / (seconds * sample_rate))
value += (goal - value) * coefficient
```

`0 ms` 时系数为 1，目标立即取得映射后的值。一个时间常数覆盖剩余距离的 63.2%。

### 学习与最近调整 {#learn-and-last-tweaked}

在编辑器中，用 **学习 CC** 为一个目标开启学习。下一个 CC 会为该控制器创建链接，并为该目标写入恰好一行。再次学习同一个目标会保留这一行及其设置，不会新增一行。没有任何行的链接会被删除。面板会记住你最后移动的参数，所以 **+ 最近参数** 可以一步把它绑定到已有的控制源，**学习 CC** 则把它绑定到新的 CC。

### 限制 {#limits-1}

- 效果器自动化轨道链接在导出和播放中都会运行，来源仍是一条可编辑的自动化轨道。
- 桌面应用监听 MIDI 输入时，CC 链接可以驱动轨道和总线插入效果的参数。每个音频块为所有目标只读取一次每个控制器。在第一个匹配的 CC 到达之前保持书写的值，之后每个目标都可以平滑这些变化。离线渲染使用书写的值和自动化。
- 命名预设的宏在桌面播放和导出中都会运行。播放时，拖动宏会预览链接的值；松开时把数值保存为一次编辑，取消则恢复原值。保存一个只用作效果架控件的预设时，正在播放的音频图会保留，延迟和混响尾音也随之保留。导出始终读取保存的预设。逐音符的调制留在音色内部。
- 链接行不导出到 MIDI，也不会创建自动化轨道；MIDI 导出从书写的 MIDI 和自动化轨道获取事件。

## 触摸接管 {#touch-override}

走带流式播放时，拖动一个有自动化的参数会接管它：你手上的值优先，自动化轨道被暂停。松开时，参数通过固定的 20 ms 交叉淡化交还给自动化轨道，所以即使相差 20 dB 也不会产生爆音。交叉淡化时长不可调整。触摸是实时状态，绝不会修改工程。它不写入任何节点，也不改变任何声明值，离线渲染始终按书写的自动化轨道求值。

这条规则是 `oc-engine::touch` 中的一个函数（`TouchLane::plan`），效果器参数自动化轨道和 `gain_automation:` 片段共用。图形界面在旋钮上用一个强调色圆环表示触摸。只有确实被自动化轨道寻址的效果器参数才会被接管，其他参数照常编辑。

按住触摸时，除了让自动化轨道静音，还会暂停它的单极点平滑器。自动化轨道的时钟继续走，但滤波后的值停在它最后控制的那个采样上，所以在你按住参数期间，平滑器不会向曲线漂移。松开时，20 ms 交叉淡化把你的值混入自动化轨道恢复后的输出，之后由自动化轨道自己的 `smoothing=` 时间常数把数值带到当前曲线值。交叉淡化只负责交还参数，本身不做平滑。100 ms 的自动化轨道仍需 100 ms 才能到达按住期间移动过的目标，而无论自动化轨道如何设置，淡化都是 20 ms。
