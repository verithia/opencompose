# OpenCompose documentation

OpenCompose is a digital audio workstation whose project is a text file. A song
is an `.ocp` document: tracks, patterns, notes, mixer settings and effects
written as readable lines instead of stored as an opaque session. The same
document can be edited by hand, generated by a model, rendered by the command
line, or played by the desktop app.

## The four faces

| Face | What it is | Start here |
|---|---|---|
| **`.ocp` language** | The project format. Human-readable, diffable, engine-agnostic. | [The .ocp file](manual/dsl.md) |
| **`ocp` command line** | Parse, validate, format, export, render, analyse, convert MIDI. | [Command line](manual/cli.md) |
| **Desktop app** | Tauri 2 window over the same engine: timeline, piano roll, mixer, device rack, patch editor, plugin browser, DSL editor, AI panel. | [The window](manual/gui.md) |
| **Rust crates** | Nineteen workspace crates behind those three faces. | [Component reference](components/index.md) |

## How this site is organised

The site follows the four documentation kinds of [Diátaxis](https://diataxis.fr),
so a page has one job and you can tell which one before reading it:

| Part | Kind | Use it when |
|---|---|---|
| Tutorials | learning | You have not built the project yet and want a working render. |
| How-to guides | tasks | You have a concrete problem: a blank window, a failing render, a broken check. |
| Reference | information | You need the exact syntax, control name, subcommand, type or tool. |
| Explanation | understanding | You want to know why the engine is built this way. |

The API reference is generated from the source with `cargo doc` and published at
[`api/`](api/index.html). It is the authority for every public type and
function; the written pages describe behaviour and link into it.

## The full map

The tables below list the product and design documents behind those pages. Each
one is also a chapter of this site.

`docs/` holds **product and design docs** (how a feature works and why, written
to be read alongside the code). Measurement logs and design provenance stay
outside the repository.

Start with [compatibility and originality](compatibility.md) — it governs what may
be written where, and every synthesis or device doc assumes it.
